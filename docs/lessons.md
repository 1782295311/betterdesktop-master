# lessons.md — 通用工程经验（本仓踩坑抽象）

> 地位：把重建过程中踩过的坑抽象为**与具体项目无关的通用规则**（项目专属陷阱见 `docs/architecture/环境陷阱.md`）。
> 格式：现象 → 抽象根因 → 通用规则 → 本仓落点。本文件是活文档：每踩一个新坑，先在此抽象，再落具体约束。

## 一、工具链与编码

1. **编码契约必须显式冻结**。现象：PowerShell 5.1 读 UTF-8 无 BOM 脚本变乱码，门禁假红。规则：任何脚本/文档体系必须显式规定「解释器 + 版本 + 编码 + 行尾」四要素，写入规范并机检。落点：AGENTS 门禁纪律第 2 条。
2. **目录结构要靠工件保证，不靠记忆**。现象：git 不跟踪空目录，新鲜克隆缺失类别目录，门禁才暴露。规则：骨架目录要么有内容要么放 `.gitkeep`；目录存在性纳入校验而非依赖提交者自觉。落点：决策记录类别目录检查。
3. **工具链升级会换默认产物**。现象：SDK 10 的 `dotnet new sln` 生成 slnx 而非 sln。规则：锁定 SDK 版本，并记录其默认产物格式；脚本引用产物时避免硬编码旧格式。落点：global.json + 门禁用 slnx。

## 二、自动化与取证

4. **暂存要精确，执行前断言工作区干净**。现象：`git add -A` 把未提交改动打包进注入提交，随 revert 全部被撤。规则：任何自动化取证/回滚脚本的暂存必须精确到文件；执行前先断言无其它未提交改动。落点：门禁契约第 8 条。
5. **脚本作用域陷阱是门禁永假的常见根源**。现象：脚本块内 `+=` 只改局部副本，父作用域集合永远为空。规则：跨作用域累加显式加作用域前缀；门禁脚本自身必须有红证（自举）。落点：common.ps1 + 九份红证。
6. **完整性判定用「必须具备什么」，不用「不得含什么」**。现象：「待填写」物证能过关；反向扫描又误伤红跑原样输出里的合法词。规则：正向完成标记可判、负向黑名单不可靠。落点：gate-registry 完成结论标记。

## 三、API 与代码设计

7. **重载要避免委托/lambda 隐式转换歧义**。现象：On 与带返回值重载并存时，返回值被悄悄丢弃且不报错。规则：公共 API 存在转换歧义时宁可改名（如 OnResult）也不可含糊。落点：IEventBus。
8. **语义不匹配的框架集成 = 双轨腐化**。现象：评估引入 MS DI 套壳服务图。规则：引入框架前先问语义是否匹配（通知/重载/生命周期）；匹配不了就自实现。落点：ADR-002 D2 否决 MS DI。
9. **静态分析升格为错误，让编译器当评审**。现象：CA2000 在 warnaserror 下立刻全红。规则：早期代码质量由编译器强制，规则先于代码。落点：TreatWarningsAsErrors + .editorconfig。
10. **状态机代码的「先快照后变更」是铁律**。现象：先置 Unloading 再读 wasLoaded，恒为假。规则：状态转换函数先快照旧状态再写新状态；用契约测试锁定状态机语义。落点：PluginHandle 修复 + 依赖重载契约测试。
11. **活文档要留预算余量**。现象：STATUS 超预算 10 词即红。规则：指针类文档设预算并留余量；超限先精简后放宽。落点：doc-budgets 21 个文档。

## 四、治理与交接

12. **规则有效性以「无记忆新人能否照做」为判据**。现象：无上下文新会话实测暴露 10 处困惑。规则：重要规则上线前做冷启动实测；新手的困惑清单就是规则缺口清单。落点：交接增强六件套。
13. **红绿双向验证是缺陷探测器，不是仪式**。现象：红证抓出「git 空目录」「md-wrap 永假绿」两个真缺陷。规则：每条门禁必须红过一次才可信；红了说明规则活着。落点：guard-redproof 九份物证。
14. **证据的可复现性高于结论的正确性**。现象：老仓 12 份伪证返工；本仓取证误打包。规则：物证要「别人照着能复现」：注入片段、原样输出、双 hash、干净环境。落点：E1–E4 取证标准。
