# 诊断日志与问题回收指引

> 适用版本：2026-09-17 起的构建（统一日志系统上线）
> 用途：分发给他人实地测试时，出了问题能"把现场拿回来"。

## 一、日志写在哪

**统一目录**：`%LOCALAPPDATA%\BetterDesktop\logs`
（在资源管理器地址栏粘贴这段即可打开；或右键托盘图标 → 「打开日志目录」）

文件命名规则：`<组件>-yyyyMMdd.log`（同一天内同名，超过 8MB 自动滚动成 `-1`、`-2`）

| 日志文件 | 由谁写 | 关注什么 |
|---|---|---|
| `host-*.log` | 主程序（**所有插件的日志都汇到这里**） | 菜单栏/Dock/桌面/右键/剪贴板/搜索… 绝大多数功能问题看它 |
| `tray-*.log` | 托盘 | 菜单动作、启停组件、系统集成注册 |
| `agent-*.log` | 常驻服务 | 能力持有/交接、看护 |
| `panel-*.log` | 剪贴板面板 | 面板显示、粘贴、热键 |
| `capture-*.log` | 截图 | 采集后端降级、HDR、编辑器 |
| `desktop-control-*.log` | 桌面服务 / 桌面控制菜单 | 桌面图标、桌面控制菜单 |
| `settings-host-*.log` | 设置中心 | 打不开设置、分区构建失败 |
| `updater-*.log` | 更新器 | 检查/下载/替换/回滚 |
| `watchdog-*.log` | 看门狗 | 组件被拉起/未拉起的判断依据 |
| `engine.log` / `index-engine.log` | 两个 Rust 引擎（自行写盘） | 剪贴板采集与文件索引 |

> 注意：本版之前，日志散落在桌面（`BetterDesktop_debug.log`）、`%TEMP%`、`%LOCALAPPDATA%\BetterDesktop\` 根目录等多处，
> 且部分文件永不清理。现在**全部收敛到上面这一个目录**。

## 二、每次启动都有"环境横幅"

每个进程启动时都会在日志开头写一段：

```
------ BetterDesktop.Host 启动 ------
  版本   : 1.3.0-2026.09.17.1544+b805f6e...
  进程   : BetterDesktop.Host.exe (pid=52792)
  系统   : Microsoft Windows NT 10.0.26200.0 / x64 / CLR 8.0.21
  目录   : ...\BetterDesktop.Host\
  日志   : C:\Users\<用户>\AppData\Local\BetterDesktop\logs
  启动于 : 2026-09-17 23:44:38
  命令行 : ...
--------------------
```

排障第一步就是看它——确认"问题出在哪个版本、什么系统上"，这一步能省掉大量来回询问。

## 三、日志级别（默认 Info，够用）

默认只输出关键事件，已经覆盖"功能成功/失败"。需要更详细时，**设环境变量后重启对应进程**：

```
BETTERDESKTOP_LOG_LEVEL = Trace | Debug | Info | Warn | Error | Off
```

- `Debug`：加详细分支/状态
- `Trace`：最啰嗦，只在定位特定问题时开
- `Warn` / `Error`：日志太大时收窄

弹窗外点收起的诊断默认**完全关闭**（它在鼠标钩子里，开销敏感）；要用时设 `BETTERDESKTOP_POPUP_TRACE=1`。

## 四、磁盘占用自动治理

| 策略 | 值 |
|---|---|
| 单文件上限 | 8 MB（超过自动滚动） |
| 保留天数 | 7 天 |
| 目录总量上限 | 256 MB（超出从最旧的删） |

测试几天不会把磁盘写满；也不会出现"几个月前的日志把目录撑爆"。

## 五、崩溃怎么查

未处理异常会写成 `[崩溃]` 开头的记录，包含：

- 来源（Dispatcher / AppDomain / 未观察 Task）、是否终止进程
- 异常类型、消息、堆栈、最多 5 层内层异常
- **环境快照**（版本/系统/目录/命令行）

并且**同步刷盘**——异步日志队列在进程被终止时会丢最后几条，而那里往往正是崩溃原因，所以崩溃路径强制落盘。

查找：在某份日志里搜 `[崩溃]`。

## 六、给测试同学：出问题怎么回传（3 步）

1. 右键任务栏托盘图标（BetterDesktop）
2. 点 **「导出诊断包（收集日志给开发者）…」**
3. 桌面会生成 `BetterDesktop-诊断包-tray-<时间>.zip` —— 直接把这个文件发回来即可

包里含：最近 20 个日志文件（最多 32 MB）+ 系统与版本信息。

> 设计取舍：不做自动上传（避免隐私与网络问题），由用户主动导出。
> 导出前会先把内存中排队的日志刷盘，保证包含"刚刚发生"的那几条。

## 七、相对上一版，诊断能力的变化

| 项 | 上一版 | 现在 |
|---|---|---|
| 管道 | 十几个进程各写各的，格式/策略不一致 | 全进程同一套实现、同一目录、同一格式 |
| 写入方式 | 多数**同步** `File.AppendAllText` | 异步有界队列 + 后台批量刷盘 |
| 热路径 | 鼠标钩子回调、Dock 悬停、缩略图链路都在同步写盘 | 热路径改为异步；钩子里的弹窗诊断默认关闭 |
| 文件上限 | 多数**永不清理** | 单文件 8MB 滚动 + 7 天 + 目录 256MB 上限 |
| 崩溃 | 只记异常消息，异步队列常丢最后几条 | 异常链 + 环境快照 + **同步刷盘** |
| 收集 | 需要手动翻多个目录 | 托盘一键导出诊断包 |
| 启动信息 | 无（不知道跑的是哪个版本） | 每进程启动横幅（版本/系统/目录/命令行） |

## 八、排查速查表

| 现象 | 先看 |
|---|---|
| 某个功能没反应 | `host-*.log`（插件日志）、对应进程日志的**失败行**（`[ERR]` / `[WRN]`） |
| 主程序启动不了 / 反复重启 | `host-*.log` 的启动横幅与 `[崩溃]`、`watchdog-*.log`（谁在拉起） |
| 组件被自动拉回 | `watchdog-*.log` + `%LOCALAPPDATA%\BetterDesktop\` 下的 `*-stopped.flag` |
| 桌面图标/桌面服务异常 | `desktop-control-*.log`、`host-*.log` 中 `shell.desktop` 标签 |
| 剪贴板不记录 | `engine.log`（Rust 引擎）+ `panel-*.log` + `host-*.log` 中 `shell.clipboard` 标签 |
| 截图失败 | `capture-*.log`（后端降级、受保护内容会明确写出） |
| 更新失败 | `updater-*.log`（含退出码语义与回滚记录） |
