# guard-redproof — 变红物证标准

> 每条门禁必须在这里留下一份「故意违规 → 变红 → 撤销 → 恢复绿」的完整物证。
> 规则真的会变红，规则才存在。一条从未红过的门禁等于没有门禁。

## 内容三要素（缺一不算数）

| 要素 | 要求 |
|---|---|
| ① 可复现的注入片段 | 违规怎么造出来的：注入的文件内容 / diff / commit hash，别人照着做能一模一样复现 |
| ② 原样拷贝的失败输出 | 门禁的真实输出**逐字粘贴**（含退出码）。禁止转述、禁止摘要成「报错了」 |
| ③ 撤销证明与 hash 验真 | 注入 commit hash + 撤销 commit hash + 撤销方式；撤销后重跑贴出「已恢复」的实际输出 |

## 取证环境四要求

| 要求 | 内容 | 对纯文档门禁的适用性 |
|---|---|---|
| E1 | 清空并重建构建产物、全程同一次构建 | 文档门禁无构建产物，标注「N/A（无构建产物）」即可 |
| E2 | 禁 `--no-build` 等跳过编译路径 | 同上，N/A |
| E3 | 禁拷贝预构建产物 | 同上，N/A |
| E4 | 记录取证时 HEAD（注入前 HEAD、注入 commit、撤销 commit 三个 hash） | **永远适用** |

## 目录约定

- 每条门禁一份物证：`<gate-id>-redproof.md`（如 `package-readme-redproof.md`）。
- 本目录被 `verify-md-links` 豁免扫描（物证内必然包含指向已撤销文件的失效引用，属历史现场，不是当前文档缺陷）。
