# 跨语言插件体系 · 实施计划

> 状态：计划（未实现）。跨语言工程的难点在"语言隔阂"——类型/内存/生命周期/错误/版本/调试每一样都要先定规则，否则 Phase 4 对接 UE5 舞台时会连环翻车。本文先把规则定完，再排实施。

## 1. 背景与动机

- 硬需求：**UE5 桌宠舞台**（PetStage，C++）、FFmpeg 视频、Everything 式索引、DSP 引擎——这些性能/生态锁死，C# 做不了或做不好。
- 原则：C# 插件体系保持干净；性能敏感块 = **独立原生进程 + IPC**；C# 侧只留一个 `ExternalPluginAdapter` 代理。

## 2. 目标与非目标

**目标**：
- `cordis.yml` 支持 `type: external` 插件（命令 + 参数 + 协议版本）。
- 宿主侧 `ExternalPluginAdapter : IPlugin`：把内核的 依赖解析/服务注册/事件总线 映射为线上协议。
- 各语言薄 SDK（Python/Node/Rust/C++），一个统一协议。
- 崩溃自愈、日志贯通、协议可回放调试。

**非目标**（明确不做）：
- 不内嵌脚本引擎（Jint/Python.NET）——隔离与崩溃安全优先。
- 不做跨语言断点调试（做不到也不值得）——用协议层诊断替代。
- 不让外部进程直接调用危险内核方法（最小暴露面）。

## 3. 语言隔阂难点清单（先定规则的地方）

| # | 难点 | 规则（草案） |
|---|------|--------------|
| 1 | **类型映射** | C#↔JSON 白名单类型：string/int64/double/bool/null/数组/字典/record；枚举按字符串传；`DateTime` 用 ISO-8601；`byte[]` Phase 1 用 base64（单条 ≤64KB），Phase 3 改共享内存 |
| 2 | **数字精度** | 跨语言一律按 JSON number；C# `long`/`ulong` 显式声明，避免 JS 端精度丢失（JSON number 安全整数 2^53 内） |
| 3 | **内存与所有权** | 小数据 = 协议体；大数据 = 命名共享内存（CreateFileMapping + 句柄 + 引用计数，Phase 3）；**谁创建谁释放**，协议层带 release 方法 |
| 4 | **生命周期** | 状态机见 §6；握手必须完成才算 READY；优雅退出走 shutdown 消息；崩溃检测 = 进程退出 + ping 看门狗；重启退避 0.5s→1s→2s…上限 30s，连续 3 次失败停启 |
| 5 | **孤儿进程** | 内核退出/Adapter 卸载时，先 shutdown 再 kill（等 2s），仍存活强杀；宿主退出由 OS 回收 |
| 6 | **错误传播** | 异常 → 错误码 + 错误消息（不带堆栈）；错误码枚举固定（PROTOCOL/UNSUPPORTED/TIMEOUT/CRASH/NOT_FOUND/BUSY…）；日志聚合：外部进程 stderr 全量进内核日志（带插件名前缀） |
| 7 | **版本兼容** | 协议 `protocolVersion` 握手协商（不匹配拒绝加载）；schema 演进规则：**只加字段、不改语义、旧字段永删**；插件与内核版本矩阵登记 |
| 8 | **并发与流** | 请求/响应按 id 关联（JSON-RPC 2.0）；事件走 notify 单向；调用可 cancel（id 取消）；超时默认 10s 可配；事件背压 = 丢弃+计数告警 |
| 9 | **调试** | 协议记录（每帧存盘，可回放重放）；ping 心跳探活；`--trace-protocol` 开关；诊断事件（重启次数/卡死计数）进事件总线 |
| 10 | **安全** | 外部进程不可信：命令/路径白名单校验、降权启动（受限令牌，Phase 2）、协议方法白名单、参数长度限制、禁止 shell 拼接（arg 数组直传） |
| 11 | **环境依赖** | 运行时发现（python/node 探测 PATH）、缺失提示进设置界面"组件管理"；SDK 自带版本自检 |

## 4. 总体架构

```
内核 IContext
   │ context.Plugin(adapter)
   ▼
ExternalPluginAdapter : IPlugin   ← 宿主侧唯一入口（其余内核代码零改动）
   │ 控制通道：JSON-RPC over stdio（Phase 1）→ 命名管道（可选）
   │ 日志通道：子进程 stderr → 内核日志（插件名前缀）
   │ 大块数据：Windows 命名共享内存（Phase 3）
   ▼
外部进程（Python / Node / Rust / C++ / UE5）
   └── 薄 SDK：connect → handshake → invoke / notify / subscribe / shutdown
```

**服务映射**：
- 外部插件"提供服务"：Adapter 把它的能力注册为内核服务（其他 C# 插件 `Get` 到的是 **RPC 代理对象**，调用即跨进程）。
- 外部插件"依赖服务"：Adapter 在内核侧查依赖，把已注册服务包装为可调用句柄，经协议暴露给外部进程。

## 5. 协议草案（v1 要点，细节 Phase 1 出）

- 帧：**stdout 专属 JSON-RPC**，消息间用 `Content-Length: N\r\n\r\n{json}`（避免日志污染与换行歧义）；stderr 只走日志。
- 方法表（草案）：
  - `handshake`：protocolVersion + capabilities + runtime 信息（进程侧 → 宿主）
  - `invoke`：`{ id, service, method, params }`；`response`：`{ id, result | error{code,message} }`
  - `notify`（宿主→进程 与 进程→宿主 双向）：`{ event, data }`
  - `cancel`：`{ id }`；`ping`/`pong`：看门狗探活；`shutdown`：优雅退出
- 错误码：见 §3 #6 枚举，统一 `error.code` 整数 + 可读 `error.message`。

## 6. 生命周期状态机

```
PENDING → LAUNCHING(启动进程) → HANDSHAKE(版本/能力协商)
       → READY → RUNNING（正常调用/事件）
                 ↓ 崩溃/退出/ping 超时
       → CRASHED → backoff 重启（0.5→1→2→…→30s，连续3次失败 → STOPPED）
       → UNLOADED（shutdown → 回收进程）
```

- 看门狗：每 5s ping，10s 无响应视为卡死 → 重启。
- 重启保留计数与诊断事件，供设置界面"组件管理"展示。

## 7. 大块数据传输（Phase 3）

- Windows 命名共享内存：`CreateFileMapping` + 句柄经协议传递（DUPLICATE_HANDLE 语义） + 引用计数 + 释放消息。
- 用例：UE5 舞台帧/缩略图、FFmpeg 解码帧、索引结果集。
- Phase 1/2 一律 base64 上限 64KB，协议层拒绝超限并报 `PAYLOAD_TOO_LARGE`。

## 8. 安全边界（Phase 2 完整化）

- 命令/路径白名单 + 参数数组直传（禁 shell 拼接）。
- 外部进程降权运行（受限令牌）；无法降权时至少限制工作目录与环境变量。
- 协议方法白名单；外部进程不得直接调用内核未暴露服务。
- 输入长度限制（参数/消息体上限）。

## 9. SDK 形态

- 每语言一个薄客户端（目标 200-400 行）：`connect(stdio|pipe)` / `handshake` / `call` / `subscribe` / `shutdown` + 服务 stub（由协议描述生成）。
- 语言包管理：Python `pip` / Node `npm` / Rust `crates` / C++ 单头文件。
- SDK 与协议版本绑定，握手失败给明确原因。

## 10. 用例与优先级

| 优先级 | 用例 | 语言/技术 | 依赖 |
|--------|------|-----------|------|
| P0 | **UE5 桌宠舞台** | C++（UE5） | 演出协议（Phase 4） |
| P1 | FFmpeg 视频（动态壁纸/缩略图） | C++/FFmpeg | 大块传输（Phase 3） |
| P1 | Everything 式索引搜索 | C++/Rust 或调 Everything SDK | Phase 1 即可起步（文本结果） |
| P2 | DSP 引擎 | Rust/C++ | 大块传输 |
| P2 | Python AI 编排（多模态桌宠） | Python | 生态非性能 |

## 11. 分阶段实施计划

| 阶段 | 内容 | 验收 |
|------|------|------|
| **Phase 1** | 协议 v1 + 宿主 `ExternalPluginAdapter`（stdio JSON-RPC）+ **Python echo 示例插件** + 单测 | 跨语言 hello 闭环；invoke/notify/cancel/shutdown 全通；`cordis.yml` 加载 external 插件 |
| **Phase 2** | 生命周期健壮性：崩溃重启退避、看门狗、孤儿回收、stderr 日志聚合、错误码完善、协议记录回放 | 杀进程 3s 内自动拉起；日志带插件名前缀；协议回放可复现故障 |
| **Phase 3** | 共享内存大块传输 + 吞吐基准 + 安全边界（降权/白名单） | 128MB 帧传输 < 100ms；基准对比 base64 收益；白名单拦截测试 |
| **Phase 4** | UE5 桌宠舞台对接（演出协议：下行 ShowEmotion/PlayAnimation/Speak/Teleport，上行 状态/完成）+ FFmpeg 视频 | 桌宠在桌面演出；动态壁纸播放；设置界面可见组件状态 |

## 12. 总验收标准

- [ ] 任意语言写一个插件能在 1 小时内接入（按 SDK 文档）
- [ ] 跨语言调用失败时错误码/日志可定位到"哪一侧哪一层"
- [ ] 外部进程崩溃不影响内核与其他插件（隔离实证）
- [ ] 协议版本不匹配时优雅拒绝并提示升级路径
- [ ] 全链路文档化：类型映射表 / 协议规范 / SDK 指南 / 演出协议

## 13. 风险与对策

- **协议设计返工**：先用最小协议跑通 Python echo，再冻结 v1（先实验后冻结）。
- **UE5 进程体积/启动慢**：舞台进程常驻 + 预热；启动失败重试退避。
- **跨语言类型边界反复**：类型映射表先行冻结，改动走版本号。
- **调试成本**：协议记录/回放是第一优先级工具，不是可选项。
