# ADR-003 · 宿主职责边界：桌面主窗归 shell.desktop，SplashWindow 为启动画面豁免

| 项 | 内容 |
|---|---|
| 编号 | ADR-003 |
| 标题 | 宿主不写业务 UI；桌面主窗归 shell.desktop；SplashWindow 作为宿主启动画面豁免 |
| 状态 | **已接受（Accepted）** |
| 日期 | 2026-09-09（补记 + 追认，一阶段收口） |
| 决策人 | 架构执行起草，主理人确认 |
| 适用范围 | `host/` 与一切宿主 UI 文件；`scripts/verify-architecture-guard.ps1` |

| 下游约束 | host 新增任何 .xaml 必须先过本文 D1/D2 判定；豁免清单只减不增 |

## 一、背景

`verify-architecture-guard.ps1` 的规则是：宿主不得携带业务 UI，一切 UI 由 shell 插件提供；host/ 下除 `App.xaml`（应用入口资源定义）外的 .xaml 一律视为违规。该门禁注释引用了「ADR-003 D2」作为依据，但 `docs/architecture/ADR-003.md` 从未存在——依据缺失。同时，`host/Views/SplashWindow.xaml` 真实存在并被门禁拦截，但其职责是**宿主启动画面**，与「业务 UI」性质不同，需要明确的边界判定。

## 二、决策

### D1 · 宿主只装配、不写业务 UI（补记现状）

宿主（`host/`）的职责被界定为：内核装配、WPF 启动、命名管道命令桥、Bootstrap。桌面主窗口与背景等**业务 UI** 由 `shell.desktop` 插件提供，宿主不得直接携带。此条是对既有实现事实的书面化（门禁 `architecture-guard` 一直按此规则执行）。

### D2 · SplashWindow 豁免：宿主启动画面属进程级 UI

`host/Views/SplashWindow.xaml` 是**启动画面**，展示于内核装配、插件加载之前——此时插件域尚未建立，任何 shell 插件都无法提供该窗口。它是宿主进程在「装配阶段」必须自行呈现的进程级 UI，不属于「业务 UI」。**决策：豁免 `host/Views/SplashWindow.xaml`**，在 `architecture-guard` 门禁中加入豁免清单（allowlist），且该清单**只减不增**；后续宿主新增任何 .xaml 必须重新走本文判定，不得援引本豁免。

## 三、后果

- 门禁 `architecture-guard` 增加豁免项 `host\Views\SplashWindow.xaml`，其余 host/ .xaml 仍一律红。
- 收口后门禁状态：architecture-guard 由红转绿（豁免有据）。
- 若未来出现「宿主在插件加载后仍需自行弹窗」的需求，须新开 ADR，不得扩张本豁免。

## 四、被否决的备选方案

| 方案 | 否决理由 |
|---|---|
| 把 SplashWindow 移入 shell 插件 | 启动画面必须在插件加载前显示；插件域未建立时无处安放，时序上不可能 |
| 删除 SplashWindow | 宿主启动期无可视反馈，长加载（内核装配 + 19 插件域）期间用户看到黑屏，体验退化 |

关联：`scripts/verify-architecture-guard.ps1`、`host/Views/SplashWindow.xaml`、[`STATUS.md`](STATUS.md)、[`ADR-001`](ADR-001.md)。 必须新开 ADR 的情形：宿主再增加任何 .xaml；豁免清单新增条目；变更 D1 职责边界。
