## 一、背景

旧仓 `cairoshell原版`（32 工程 / 753 个 .cs / 双 TFM）已有成熟的扩展宿主（`ICairoPlugin` + `ExtensionService` + ALC 热插拔）与治理文化（ADR、棘轮、变红物证），但三件事决定了它不适合继续作为地基：

1. **形态不匹配**：它是「外挂式扩展宿主」，内核功能本身不是插件；Cordis 的「一切皆插件 + 服务图 + 依赖驱动重载 + 托管生命周期」无法在旧结构上增量获得。
2. **双 TFM 包袱**：net480 侧 ALC 不可回收，HMR 与插件隔离在旧仓永远打折扣。
3. **文档无机器校验**：包级 README 覆盖率 1/32；断链、预算、决策记录格式全靠人肉。

2026-08-19 用户拍板：**推翻旧仓内改造路线，另起炉灶全量重写**，旧仓转为只读行为参考。

## 二、决策

### 2.1 四项基线决策（用户已确认）

| # | 决策 | 内容 |
|---|---|---|
| D1 | 位置与命名 | 新仓 `better-desktop-cordis`，与 cairoshell 结构明确切割 |
| D2 | 技术基线 | 仅 `net8.0-windows` + WPF，**放弃 net480**（ALC 可回收是 HMR 的前提） |
| D3 | 第一步范围 | 只做 P0 地基：宪法 + 门禁 + 决策记录制度 + 变红物证，**不写任何业务代码** |
| D4 | 旧仓资产边界 | 旧仓只读；逻辑代码零复制；**主题、图标、XAML 一律不复制**；唯一可借鉴的是白名单内的原生结构体布局（逐条 ABI 核对，登记 `docs/MECHANISMS.md` M4） |

### 2.2 宪法七条红线（不可协商）

| # | 红线 | 强制手段 |
|---|---|---|
| R1 | **门禁先于业务**：第一条业务代码落地前，门禁全绿且每道都有变红物证 | `scripts/run-gates.ps1` + `docs/guard-redproof/` |
| R2 | **每阶段可运行**：阶段结束必须可构建、可启动、可当外壳用；主干红灯窗口 ≤ 1 个工作日，超时回滚 | 阶段验收判据（见重建方案） |
| R3 | **棘轮单向**：白名单与基线只能减不能增（多闸锁定） | `verify-package-readme` 双锁；后续门禁同构 |
| R4 | **物证真实**：变红物证须满足三要素 + 取证环境 E1–E4；伪证整批作废 | `docs/guard-redproof/README.md` |
| R5 | **旧仓只读**：行为参考规格；逻辑零复制；资产白名单制 | `docs/MECHANISMS.md` M4 + code review |
| R6 | **一个关注点一套机制**：机制唯一化注册表 | `docs/MECHANISMS.md` |
| R7 | **决策留痕**：非平凡决策必附决策记录；事故必附 post-mortem | `verify-agent-note` / 归档密封门禁 |

### 2.3 内核设计方向（P1 目标，此处冻结）

- **一切皆插件**：loader、HMR、logger、ShellBar、Taskbar 全走同一 `Plugin` 通道。
- **服务图**：`Context` 提供/读取服务，`extend/isolate/intercept` 三层派生；插件声明 `inject`，依赖可用前保持 PENDING，服务变化经通知触发自动重载（epoch 去重防通知风暴）。
- **托管生命周期**：`effect` 注册清理器，卸载时逆序并行执行、单条异常隔离；事件五种分发（emit/parallel/serial/bail/waterfall）。
- **loader 不做拓扑排序**：依赖顺序完全由 inject 机制解决。
- **HMR**：双 ALC 切换、旧配置迁移、显式状态迁移接口、失败回滚。
- **C# 现实约束**：不使用透明代理（显式 `Get<T>` + 缓存委托）；WPF UI 操作一律经内核提供的 Dispatcher 服务封送 STA 线程；内核自身线程池运行。

### 2.4 双重纠错机制落地

第一层「文档贴近代码」：包级 README 100% 覆盖（含 Known Limitations）、决策记录、post-mortem。第二层「机器对齐」：`run-gates` 统一入口；首期五道门禁（README 棘轮 / 决策记录格式 / 归档密封 / 链接锚点 / 字数预算）；时机分级（本地手动 → CI，P1 起加 pre-commit）。

## 三、后果

**接受的代价**：P0 无用户可见功能；主题/图标/UI 全部重建，工作量大于改造路线；短期速度慢于「先搬过来再说」。

**获得的收益**：内核级热重载与插件隔离成为一等能力；历史债与双 TFM 包袱不带入新仓；每一包可独立验证；文档与代码由机器对齐而非人肉对齐。

## 四、被否决的备选方案

| 方案 | 否决理由 |
|---|---|
| A. 旧仓内绞杀者迁移 | 用户拍板推翻；扩展宿主形态与内核形态结构性冲突；受旧 ADR 冻结项牵制 |
| B. 沿用 cairoshell 命名 | 用户要求与旧结构明确切割 |
| C. P0 + P1 连做 | 违反 R1：门禁未经红绿验证就开始写内核 |
| D. 照搬 DSH 的 Node/TS 脚本体系 | 引入 Node 运行时；C# 项目用 PowerShell 原生实现，零新依赖 |
| E. 保留 net480 | ALC 不可回收，HMR 与插件卸载不可行 |
| F. 复制旧仓主题/图标 | 用户明确否决（D4），视觉资产全部重建 |
