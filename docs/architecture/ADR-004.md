# ADR-004 · 依赖治理：NuGet 锁定文件 + 运行时依赖选型背书

| 项 | 内容 |
|---|---|
| 编号 | ADR-004 |
| 标题 | 全仓启用 RestorePackagesWithLockFile；9 个运行时 NuGet 包逐个背书 |
| 状态 | **已接受（Accepted）** |
| 日期 | 2026-09-09（一阶段收口） |
| 决策人 | 架构执行起草，主理人确认 |
| 适用范围 | 仓库内全部 csproj（`Directory.Build.props`）与 `packages/` 全部运行时依赖 |
| 上游依据 | [`ADR-001`](ADR-001.md) 红线 R1/R2（门禁与可复现）；用户收口清单「依赖治理」项 |
| 下游约束 | 新增任何 NuGet 包必须先经本 ADR 类背书（用途/风险/替代），不得静默引入 |

## 一、背景

一阶段收口盘点发现：仓库 47 个 csproj 共引入 12 个 NuGet 包（9 个运行时 + 3 个测试基础设施），此前**无版本锁定机制**（`dotnet restore` 在浮点版本下每次可能拉到不同传递依赖），**无选型记录**（每个包为什么用、风险在哪、替代方案为何被否，均无文档）。依赖治理的目标：构建可复现（任意机器/任意时刻 restore 结果一致）+ 选型可审计（每个依赖有据可查）。

## 二、决策

### D1 · 启用 NuGet 锁定文件（可复现构建）

仓库根 `Directory.Build.props` 设置 `<RestorePackagesWithLockFile>true</RestorePackagesWithLockFile>`，全部 47 个项目 restore 时生成/校验 `packages.lock.json`（当前 44 个项目有依赖，生成 44 份锁文件）。锁文件**提交进版本库**；依赖图变更必须显式反映在 lock 差异中，杜绝「我这边能编」的隐式漂移。

### D2 · 运行时依赖选型背书（9 个）

| 包 | 消费方 | 用途 | 选型理由 | 风险与替代 |
|---|---|---|---|---|
| `ManagedShell` | shell-app-source / shell-desktop | Windows Shell 互操作：应用图标提取、Shell 集成 | 与系统 Shell 深度对接的成熟封装，避免手写 COM 枚举 | 版本跟随系统 API 演进；替代为手写 P/Invoke（已收口到 shell-core/Native），成本高 |
| `LibreHardwareMonitorLib` | shell-menu-bar | CPU/硬件监控面板 | 开源硬件监控标准库，支持 WinRing0 类内核驱动场景 | 需随 Win11 内核更新跟进；替代为 WMI（实时性差） |
| `Markdig` | shell-convert | Markdown 解析与渲染 | .NET 生态最活跃的 CommonMark 实现 | 渲染扩展点多，锁定版本防行为漂移 |
| `PDFsharp` | shell-convert | PDF 合成 / 加密 | 纯托管 PDF 生成，无原生依赖 | 加密套件有限；替代为 MigraDoc（额外依赖） |
| `ReverseMarkdown` | shell-convert | HTML → Markdown 转换 | 与 Markdig 组合构成转换引擎双向能力 | 对复杂 HTML 保真度有限，属已知限制 |
| `SkiaSharp` | shell-convert | 图像引擎（缩放/格式转换） | 跨平台图形库，性能与质量均衡 | 体积较大；替代为 WPF Imaging（格式覆盖窄） |
| `System.Drawing.Common` | shell-convert | Windows GDI+ 图像互操作 | 系统内置，兼容旧格式 | Windows-only，由 TFM `net8.0-windows` 约束 |
| `TinyPinyin.Net` | shell-dock | 拼音匹配（Dock 搜索） | 轻量拼音库，适合候选词匹配 | 多音字覆盖有限；替代为分词引擎（过重） |
| `YamlDotNet` | kernel-loader / shell-convert | 声明式插件树 YAML 配置解析 | YAML 解析事实标准，配置即文档 | 反序列化绑定需显式 schema，防注入 |

### D3 · 测试依赖（3 个，不做运行时背书）

`Microsoft.NET.Test.Sdk` / `xunit` / `xunit.runner.visualstudio` 为测试基础设施，跟随 SDK 与 xunit 官方发布，不构成运行时风险面。

## 三、后果

- `packages.lock.json` × 44 提交入库；CI/本地 restore 均按锁文件解析。
- 新增依赖必须过本 ADR 类背书（用途/风险/替代三栏齐备），由 `verify-package-readme` 类门禁从文档侧兜底。
- 构建可复现性提升；依赖漂移显式化。

## 四、被否决的备选方案

| 方案 | 否决理由 |
|---|---|
| 仅锁定顶层版本（不加 lock 文件） | 传递依赖仍漂移，可复现目标不达成 |
| 改用 Central Package Management（CPM） | 收口阶段引入全局版本中心，改动面大；lock 文件已达成可复现，CPM 留待后续 |
| 自研替代全部依赖 | 成本与维护不可承受，违背「功能层选最优语言/库」原则 |

## 五、关联文档与触发条件

关联：`Directory.Build.props`、各项目 `packages.lock.json`、[`ADR-001`](ADR-001.md)（R1/R2）。 必须新开 ADR 的情形：新增运行时 NuGet 包；变更 lock 治理策略（如改 CPM）；引入带原生/内核级风险的依赖。
