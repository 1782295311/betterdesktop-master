# pluginization.md — 插件化行为规范（快速替换与崩溃隔离）

> 地位：插件化**行为**的唯一真相源（MECHANISMS.md M14）。与 `docs/extension-rules.md` 的分工：契约管「插件长什么样」，本文件管「换起来是什么感觉」。
> 目标：社区对 shell 不满意的任何部分，都能**快速替换而不引发崩溃**——替换要像换主题一样安全。

## 一、角色插槽模型

1. Shell 的功能面 = **角色**（如 `shell.bar` / `shell.taskbar` / `shell.desktop` / `shell.start` / `shell.tray`），每个角色对应内核服务图上的一个服务名。
2. 内置实现是角色的默认提供者；社区插件 `provide` 同名服务即发起替换。
3. 依赖者的重载由内核自动完成（inject 机制，ADR-001 §2.3 已冻结）：新提供者就绪 → 依赖者自动重载 → 旧提供者卸载。**插件开发者不需要写任何通知代码**。
4. 角色清单是公开文档（P2 起 `gen-role-catalog --check` 保新鲜度），社区按清单找插槽。

## 二、替换原子性：先立后破

1. 替换时序固定：新 ALC 加载 → 新 fiber 初始化 → 依赖检查 → **新提供者激活** → 旧 fiber 卸载（逆序清理）→ 依赖者重载。
2. 任一步失败 = 整体回滚：旧实现继续服务，新 fiber 标记 FAILED 并降级上报。**禁止出现桌面中间态**（空桌面 / 半渲染 / 悬挂）。
3. 替换全程有超时上限，超时按失败回滚。

## 三、崩溃隔离分级

| 级别 | 形态 | 适用 | 崩溃后果 |
|---|---|---|---|
| L0 | 进程内 + PluginGuard | 默认：轻 UI 插件 | fiber 边界隔离：禁用该插件 + 回退默认 + 上报 |
| L1 | 进程外 worker + IPC | 重资源 / 不可信插件（声明制） | 子进程崩溃不影响主进程；按策略重启或停用 |

1. 插件声明隔离级别（plugin.json `isolation` 字段，默认 L0）；内核按风险给出建议，用户可调整。
2. 内置核心面永远 L0 但受最强护栏；**默认实现永远可用**——它是回退锚点，是「不引发崩溃」的最后防线。

## 四、熔断与回退

1. 同一插件连续崩溃 **3 次** → 熔断：自动禁用 + 回退默认实现 + 用户可见提示；解除条件 = 用户手动解除或新版本更新。
2. 回退路径恒在：状态中心提供一键「恢复内置」；禁用状态持久化，防止循环崩溃（启动即崩的插件不会反复拉起）。
3. 熔断事件必须降级上报并记入日志（与 runtime-health.md 联动）。

## 五、快速替换的用户路径

1. 安装 = 把插件目录放入用户级 `Plugins` 目录（无需管理员权限）。
2. 发现 → 清单校验 → 声明替换角色 → **热切换（无需重启）**；开发期的同一机制即 HMR（触发器不同，机理相同）。
3. 插件状态中心：显示每个角色的当前提供者、健康状态，支持一键禁用 / 回退 / 更新。

## 六、兼容性与安全护栏

1. 插件声明最低内核 ABI 版本（`kernel-abi` 字段）；不匹配 → **拒绝加载 + 明确报错**（不崩溃、不静默）。
2. 必需依赖缺失 → 拒绝激活；可选依赖缺失 → 降级启动并上报。
3. 替换属于代码执行敏感操作：安装需用户确认；来源与签名策略见 `docs/security.md`。

## 七、验收判据（P2/P3 swap drill，物证制）

1. 替换演练：换掉 ShellBar 插件 → 全程无崩溃、无空白桌面、切换完成 ≤ 目标值、一键回退成功——物证按门禁单测标准落盘。
2. 崩溃注入演练：注入必崩插件 → 自动回退 + 降级上报 + 外壳存活——物证。
3. 状态中心演练：全流程用户可感知、可操作——物证。
