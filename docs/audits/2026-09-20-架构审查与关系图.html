一句话结论：结构与边界健康，长跑资源与发布通道不健康。 这是一套工程纪律极强的项目——依赖图零环零反向、门禁带棘轮与物证、六层架构与所有权矩阵已制度化；但项目正处 「8 进程网状互拉 → core 唯一常驻」的迁移中途（S4–S8 未完），发布路径被 B1 阻塞，今晚（09-20）体检新抓到 两个 P0：core 私有工作集单调增长、一条真实的「第二生命周期所有者」越权。

二、架构关系图 · 六层进程拓扑（过渡期现状）

设计要点：core（Rust）是唯一常驻，只做九件事（托盘 / 热键 / 控制管道 / 监护 / 电源 / 安全 / GPU 仲裁 / 独占能力 / ShellMenu 快照触发），禁止加载 UI、渲染、持业务状态、读业务数据、引用 C#； 数据面引擎（剪贴板 / 索引）由 core 拉起并按需自退；表面层经 core 控制管道协作而非互相拉起。 右下「退役区」：Tray / Watchdog / Agent 已被 core 取代（S4–S5），安装根残留旧 exe 请勿双击。

五、审查发现 · 问题清单

5.1 P0（今晚体检新增，真机实证）

  • P0core 私有工作集单调增长，D2（<8MB）长跑失守：同一 PID 75 分钟内 0.53 → 14.29 → 36.83 MB，句柄 510，稳定不回落。候选根因：supervisor.rs:579 每 3 秒 Settings::load()（读文件+解析 JSON）。可执行下一步：改用 start_config_watch 文件变更通知驱动失效，替代轮询读盘。项目已推翻「D2 达标」旧读数。
  • P0一条真实的「第二生命周期所有者」：packages/shell/shell-index-ipc/IndexEngineLauncher.cs 的 EnsureEngine/StartDetached 被 shell-search 与 shell-app-source 直接调用（壳插件自己拉起进程）。真机抓到：Index.Engine.exe 父进程不是 core。门禁旧正则只匹配两段 exe 名而漏三段名——已修正则、补登记棘轮（removeBy: S6）、加回归钉子，但收敛未做（登记 ≠ 修复）。

5.2 发布 / 迁移阻塞 B1–B4

  • B1发布路径阻塞：packages/ + host/ 未提交工作区 ⇒ 构建/测试不可信；门禁两红（dotnet-format 5532 处 / test-coverage 退出码 1）均为其下游症状（证据：本次改动未触碰 C# 工程）。
  • B2Kernel.dll 多副本偏斜：4 份拷贝版本不一致，曾搞坏过面板。红线：只允许单拷 core，绝不手工拷 Kernel.dll / 任何 C# 程序集。
  • B3部署的 CLI 是 09-18 旧构建：--core 返回 Usage=2（不认识新参数）。
  • B4S4-4/5 未完成：Agent/Watchdog 源码已删，但安装根残留 Tray/Watchdog/Agent 旧 exe——勿双击，会与 core 打架。

5.3 其他（中等 / 待决）

  • 中shell 组件真机 degraded：desired=running 但 actual=False；desktop 在 1154s 内重启 6 次——需查 core 日志拉起失败原因。
  • 中安全档位不一致：engine/src/ipc.rs、engine-index/src/ipc.rs 的 CreateNamedPipeW 传 None（默认 DACL），与 core 显式 ACL 不在同一档——需显式决策（补 ACL 或登记 known-exceptions）。
  • 中文档-实现偏差 3 处：core 实际 exe 名 betterdesktop-core.exe（小写连字符）vs 文档表 BetterDesktop.Core.exe；launcher 终态描述待更新；STATUS.md（09-14）已过期仍自称第一入口。
  • 中命名漂移 4 组：CreateEngine/EnsureEngine/StartEngine（≥3，漂移）、CreateFile/LaunchFile/StartFile、LaunchDesktopService/StartDesktopService、LaunchHost/StartHost（=2，候选）。
  • 好门禁自我加固已完成：18 道 16 绿 2 红；新增 B5（组件名双向对账：components.json 9 = C# 9）；防「静默通过」三防线（枚举防空、单测反例、JSON 解析失败即判定无效）；收敛后 lifecycle-owner 16 → 13 命中。

5.4 待决（需用户拍板，来自项目自身体检）

  • 是否接受 engine/engine-index 管道默认 DACL（登记）还是补齐 ACL；
  • 数据面引擎的命名管道算不算「命令通道」（决定管道服务端归属门禁口径）；
  • 命名漂移是否统一（术语变更需先落决策记录）；
  • 「整理 = git 提交」类动作是否执行（当前 packages/ 380 项 + docs/ 未提交，git 提交属敏感操作，未动）。
