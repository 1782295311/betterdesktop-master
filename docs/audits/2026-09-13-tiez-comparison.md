# 对标报告 · TieZ Clipboard vs BetterDesktop 剪贴板

> 对象：`D:\迅雷下载\tiez-clipboard-master`（Tauri 2 + Rust + React/TS，GPL-3.0，作者 jimuzhe）
> 方法：只读代码审查（前端功能面 + Rust 后端实现两路并行）。
> ⚠️ **许可证前提**：该项目为 **GPL-3.0**。GPL 具有传染性 —— **不得复制其代码进本项目**。
> 本文只提炼**思路与算法**（思路不受版权保护，代码表达受保护），实施时必须自行实现。

## 0. 一句话总评

**它胜在 Win32 细节的打磨深度，我们胜在架构分层与数据安全；两者的产品定位不同，不应逐项对标。**

- TieZ 是**独立剪贴板产品**（Tauri 单机应用），把"捕获时序 / 粘贴兼容 / 格式透传"这些**用久了才会遇到的坑**逐个填平 —— 这部分经验对我们价值最高。
- 我们是**系统外壳的一个扩展**（引擎 + IPC 契约 + WPF 面板 + 宿主集成），强项是分层解耦、全库加密、精确去重、可访问性；而云同步/局域网/AI 这类"独立产品能力"对我们是**范围外**，不该直接对标。

## 1. 架构与存储对比

| 维度 | 我们 | TieZ | 判断 |
|---|---|---|---|
| 捕获 | 广播 + 500ms 轮询 | `AddClipboardFormatListener` **事件驱动**（非 Windows 退化轮询） | 相当；它的事件驱动更省电 |
| 同一次复制的多格式写入 | 固定延时 | **渐进重试调度** `[0,40,80,140,220,360,560]ms` + 来源应用判定 + 快路径跳过富文本探测 | **它更好**（Office/WPS 分步写格式，固定延时要慢或丢格式） |
| 存储 | 单 JSON 全量加密（DPAPI）+ 外部文件目录 | **SQLite（WAL）** + 分表 + 10 个版本化迁移 + 附件外置 | **它更稳**；我们万条规模的全量重写是隐患 |
| 去重（文本） | SHA256（Text/Html/RTF **统一按纯文本**） | 规范化后 SipHash u64 + 原文双保险 | 我们口径更严 |
| 去重（图片） | **像素级 SHA256**（RGBA+尺寸） | 32×32 Nearest 缩略图哈希 | **我们在精确性上更好**（它可能把"相近但不同"的图误合并） |
| 回环抑制 | `listener.suppress(n)` **计数抑制** | **内容哈希 + HTML 哈希 + 图片视觉哈希**，10s 时间窗比对 | **它更稳**：一次写回触发多次捕获时，计数会数错（漏吞或误吞） |
| 加密 | **全库 DPAPI** | 仅 `sensitive` 标签条目加密（其余明文落盘） | **我们更好** |
| 容量策略 | 10000 条 + **软预算提醒**（不自动删） | 500 条硬上限，自动删最旧（置顶/带标签豁免） | 取向不同；我们更保守（不静默删用户数据） |
| 多显示器 | 主屏 WorkArea | **跨屏位置按比例重映射并夹取** | 它更完整 |
| 面板形态 | 侧边栏 + 手柄拖拽（可配收起策略） | 贴边收纳 / 跟随鼠标 / 悬浮预览子窗 | 取向不同 |
| 数据同步 | 无（本地优先） | WebDAV + MQTT + 局域网 HTTP 互传 | **产品定位差异**，非缺陷 |

## 2. 功能对比

### 2.1 双方都有（各自实现）
收藏/置顶 · 搜索（我们下沉引擎、它有 `tag:` 限定）· 类型筛选 · 按序（顺序）粘贴 · 数字键快速粘贴 · 虚拟列表 · 图片/GIF 捕获与写回 · 多格式写回（CF_HDROP + 位图）· 表情/emoji 相关 · 单实例 · 开机自启 · 快捷键可配 · 深浅色主题。

### 2.2 它有、我们没有（按借鉴价值排序）

| # | 能力 | 它的做法 | 对我们的价值 |
|---|---|---|---|
| 1 | **按应用的清洗/忽略规则** | 每个来源应用可设 `ignore` 或**正则替换/丢弃**（`AdvancedSettingsGroup.tsx`、`pipeline.rs:190-222`） | 高：我们只有硬编码隐私黑名单，无法应对"某应用总是复制垃圾" |
| 2 | **粘贴到原窗口** | 用 `LAST_ACTIVE_HWND` + `AttachThreadInput` + `SetForegroundWindow` **可靠恢复焦点**后注入（`clipboard_ops.rs:435-487`） | **高**：我们正因为"焦点归还不可靠"而删掉了双击粘贴 —— 它证明了可靠做法 |
| 3 | **三档按键注入** | `扫描码 Ctrl+V`（游戏）/ `Shift+Insert`（终端，默认）/ `逐字符 Unicode`（游戏模式，处理 IME）（`clipboard_ops.rs:940-1295`） | 高：我们只有一种 `keybd_event Ctrl+V`，在终端/游戏里粘不上 |
| 4 | **命名格式透传** | 捕获时保存 RTF/表格等**自定义剪贴板格式**，写回时 `RegisterClipboardFormat` 还原（Excel 表格回贴仍可编辑） | 高：我们的富文本回贴会"降级"，表格变文本 |
| 5 | **视觉哈希回环抑制** | 见 §1 | 高：替换我们的计数抑制，改动小、收益直接 |
| 6 | **渐进式富文本探测** | 见 §1 | 中高：修复"从 Office/WPS 复制富文本偶尔丢格式" |
| 7 | **敏感信息识别 + 预览脱敏** | 正则识别手机/身份证/邮箱/密钥 → 打 `sensitive` 标签 + 预览遮罩（可配前后可见位数、邮箱域名隐藏、敏感图高斯模糊） | 中高：隐私场景；我们仅有来源黑名单 |
| 8 | **临时粘贴** | 粘贴前快照剪贴板，250ms 后**还原**（`clipboard_ops.rs:288-363`） | 中：不污染用户剪贴板 |
| 9 | **标签系统（多色 + 管理页）** | 标签表 + 计数 + 改名/改色 + 拖拽排序 + `tag:` 搜索 | 中：我们契约有 `SetEntryTags` 但**面板无入口**，等于半成品 |
| 10 | 色值就地渲染（`#hex` → 色块） | 前端识别纯色值文本 | 低（但讨喜） |
| 11 | 外部编辑器协作回写 / AI 三模式 / 局域网互传 / 云同步 / 主题商店 | — | 低：超出我们的产品范围 |

### 2.3 我们有、它没有

| 能力 | 说明 |
|---|---|
| **全库加密** | 它只加密 `sensitive` 条目，其余历史**明文落盘**（含你复制的密码片段、聊天内容） |
| **像素级精确去重** | 它用 32×32 缩略图哈希，理论上会把"视觉相近但内容不同"的图合并 |
| **按序粘贴的内容快照** | 我们的队列自包含内容 —— 条目中途被删/被清理也能粘出来；它依赖条目仍存在 |
| **表情包标记制** | 任何条目（含**文字颜文字**）都能标记为表情包并豁免清理；它是独立的 emoji 库 |
| **可访问性与键盘全路径** | UIA 可访问名 + Tab/方向键/Enter/Delete/空格/数字键 + 可见焦点；它只有上下键与 Enter |
| **软预算而非硬删除** | 超限只提醒 + 一键清理未收藏，不静默删用户历史 |
| **宿主深度集成** | 桌面/右键菜单/服务图/单实例信号；它是独立应用 |
| **双通道复制** | 普通复制 vs Ctrl+纯文本（`CF_HDROP` 与否可控）——解决"文件夹被聊天框展开" |

## 3. 建议采纳（按优先级）

> **实施状态（2026-09-13）**：P0 两项**已完成并真机验证**；**P1-3（三档注入，先落两档）已实现，
> 但默认仍是 `Ctrl+V`** —— 详见文末"实施记录 · P1-3"，那里同时记了一次**由用户实测纠正的错误前提**。

| 优先级 | 项 | 为什么先做它 | 预估改动 |
|---|---|---|---|
| P0 | **回环抑制改为"内容哈希 + 时间窗"** | 计数抑制（`suppress(n)`）是**正确性隐患**：写回若触发多次捕获事件会数错，导致"自己写回的内容又被记一条"或"真的用户复制被吞掉"。改为哈希比对是根治 | 引擎小改（写回时记哈希、捕获时比对） |
| P0 | **粘贴到原窗口（AttachThreadInput 恢复焦点）** | 恢复"点一下直接贴到刚才那个窗口"的体验（我们曾因不可靠而删掉该交互，它给出了可靠实现路径） | 引擎 + 面板；需真机验证多应用 |
| P1 | **三档按键注入** | 终端（Shift+Insert）与游戏（扫描码）是真实用户的日常场景，现在这两类地方粘不上 | 引擎中等 |
| P1 | **命名格式透传** | 解决"Excel 表格复制回来变文本"这类**内容降级**（用户会认为工具不可靠） | 引擎中等（需白名单 + 体积上限 + 安全过滤） |
| P1 | **按应用清洗规则** | 让用户自己治"某应用复制的垃圾"，不再依赖我们猜 | 引擎 + 设置界面 |
| P2 | 渐进式富文本探测 / 敏感脱敏 / 临时粘贴 / 标签体系补全 | 体验与隐私增强 | 各自独立 |
| — | **不采纳**：云同步、MQTT、局域网互传、AI 对话、主题商店 | 与"系统外壳扩展"的定位不符，且引入网络面与合规成本 | — |

## 4. 附：它的一处"看起来聪明但要小心"的设计

**把自定义剪贴板格式塞进 HTML 注释里持久化**（`clipboard/mod.rs`）——无需额外表列即可让附加格式随条目与同步一起走。
**我们若做命名格式透传，应使用独立字段存储**，而不是内联进 HTML：注释内联会让内容变得"看起来是 HTML 其实夹带二进制"，
污染搜索/预览/导出，也让体积上限难以独立控制。

## 6. 实施记录（P0 两项，2026-09-13）

### P0-1 · 回环抑制改为内容指纹 —— 已完成并真机验证
- **改动**：`listener.rs` 的"消费式抑制计数"（`suppress(n)` / `consume_suppress`）替换为
  `mark_echo(指纹)` / `take_echo(指纹)` / `clear_echo()`（**2 秒窗口，指纹 = `ClipboardEntry::fingerprint()`**）；
  `cmd_copy` 改为**先登记、再写回**（写回失败则清除）；回环判定从 `should_capture` **移到** `on_clipboard_update`
  构造条目之后（指纹要读完快照才算得出）。
- **测试**：新增 3 个语义测试 —— 自己的写回被吞且只吞一次 / **窗口内别的内容不得被吞**（旧实现最易误伤路径）/
  0 次触发的残留标记不得误吞用户复制。Rust **94 passed**。
- **真机**：写回自己的条目 → 引擎日志出现 `echo suppressed: own write-back (fingerprint match)`、条目数 **18→18**；
  随后复制**别的内容** → 正常记录、条目数 **18→19**（无义吞）；清理后回到 18。

### P0-2 · 粘贴回原窗口 —— 已实现（需人工确认手感）
- **新增** `shell-core/Windows/WindowActivator.cs`：AttachThreadInput 范式（绑定本线程 + 前台线程 + 目标线程）
  → `BringWindowToTop` → `SetForegroundWindow` → 失败再用 ALT 抖动兜底；与 `RunningAppDetector.ActivateWindow`
  同范式但只做"置前"一件事（未合并，避免动已验收的 dock 逻辑）。
- **面板**：**行中键单击** = 复制并粘贴回原窗口（`PasteEntryToTargetWindow`）。
  顺序：**先收起（`OnBeforeHide` 已用 WindowActivator 归还前台）→ 再显式激活 → 延迟 120ms 注入**
  （激活异步生效，立刻注入会打进旧前台）；注入期间复用 `_hookPaused` 放行键盘钩子（与按序粘贴同构）。
- **入口（2026-09-13 最终裁定）**：默认入口 = **鼠标中键**（唯一，不必配置）；
  键盘入口不硬编码 —— 用户在**设置 → 剪贴板 → 快捷键 → 粘贴回原窗口**自行录制
  （存 `extensions.clipboard-history.paste-back-hotkey`，面板每次打开时读取并注册到**自己窗口**、
  收起即注销）。迭代史（四轮）见 `packages/shell/shell-clipboard-panel/README.md` 的入口教训段。
- **真机验证（2026-09-13 自动化完成）**：临时配 `Ctrl+Shift+J` → 日志
  `用户热键已注册：Ctrl+Shift+J`；UIA 选中第一条后按键 → `用户热键触发` →
  `收起面板：已把前台归还` → `粘贴回原窗口：target=0xB41000 activated=True` → `已注入 Ctrl+V`（全链路通）。
  未选中项时走提示分支（`用户热键：列表无选中项 → 提示用户先选中`），不静默。
  注：含 `Alt` 的组合在 `keybd_event` 注入下**测不出来**（系统菜单/IME 抢先），换 `Ctrl+Shift+J` 即通 ——
  这是注入方式的局限，不是产品结论。
- **待人工确认**：注入落在哪个窗口需人眼确认（自动化只能验证"已注入"，判定不了落点）。

### P1-3 · 三档按键注入（先落两档）—— 已实现，**默认保持 `Ctrl+V`**
- **原始问题（部分成立）**：`SendPaste` **恒发 `Ctrl+V`**，在**少数终端**（`mintty`(Git Bash/MSYS2)、
  `PuTTY` 等 SSH 客户端）里 `Ctrl+V` 是字面输入而非粘贴 → 那里"粘贴回原窗口"没反应。
- **⚠️ 我犯的错（由用户实测当场纠正）**：我按"终端里 Ctrl+V 不粘贴"的**过时印象**开了一份白名单，
  把 `WindowsTerminal` / `conhost` / `cmd` / `powershell` / `pwsh` 也列为"要换成 Shift+Insert"。
  用户实测原话：**"我使用 Ctrl+V 可以粘贴到 powershell 和 cmd 里面啊"**。
  事实是 **conhost 自 Win10 1809 起就支持 Ctrl+V**，`cmd` / PowerShell / Windows Terminal 全部支持。
  **拿过时印象去改默认路径 = 用回归换修复** —— 而且用户完全不知道发生了什么（最坏的一类改动）。
- **最终改动**：
  - 新增 `PasteInjectMode`（**`CtrlV` 默认** / `Auto` / `ShiftInsert`）与 `ClipboardIpcClient.InjectMode`；
  - **默认 = `CtrlV`（等同旧行为，零变化）**；白名单大幅收窄到**确实不认 Ctrl+V** 的：
    `mintty`、`putty`、`Xshell`、`SecureCRT`、`MobaXterm`（且仅当用户选 `Auto` 时才生效）。
    判定原则写进代码注释：**宁可漏判（用户可手动切），不可误判（擅自换掉能用的键）**。
  - 判定失败（取不到进程）→ 按"非终端"处理，保持 `Ctrl+V`。
  - 设置界面「粘贴按键方式」三选一，**第一项（默认）就是"总是 Ctrl+V"**，并在提示里写明
    "cmd / PowerShell / Windows Terminal 都支持 Ctrl+V"。
- **新增观测点**：`ClipboardIpcClient.LastInjectKey` + 面板日志
  `粘贴回原窗口：已注入粘贴按键（Shift+Insert）`。此前日志写死"已注入 Ctrl+V"，
  排障时**根本看不出按的是哪个键**（本轮第一个卡点）。已改为回报实际按键。
- **验证**：
  - 单测 22 个用例（`PasteInjectModeTests`）：**把用户实测的反例钉死在 `false`**
    （`cmd` / `powershell` / `pwsh` / `conhost` / `WindowsTerminal`），
    外加 mintty/PuTTY 判 true、普通应用与 VS Code 判 false、空/null 按非终端处理。
  - 真机日志证明切换机制生效：`target=0x2D40B40 activated=True` → `已注入粘贴按键（Shift+Insert）`。
- **未做到的部分（如实记录）**：**"内容是否真的落进终端"自动化验证不了** ——
  Windows Terminal 主窗口不支持 UIA `TextPattern`（读不回文本），cmd/conhost 同样读不回；
  用"粘贴命令 + 回车看文件是否生成"的间接探针也失败，但那次**前台窗口不可控**
  （`ExecuteCommand` 的宿主终端可能才是真正的目标），**不能据此判定功能失败**。
- **未采纳**（记录以备将来）：TieZ 的"扫描码注入（游戏）"与"逐字符 Unicode（游戏 + IME）"两档 ——
  收益场景小众、实现面大；若要加，入口就在 `PasteInjectMode` 上加枚举值。

### P1-4 · 命名格式透传 —— 已实现（需人工确认表格回贴）
- **新模块** `engine/src/formats.rs`：`EnumClipboardFormats` 枚举 → `GetClipboardFormatNameW` 反查名字
  （无名 = CF_ 标准，跳过）→ 排除已单独处理的格式（`CF_UNICODETEXT`/`CF_DIB`/`CF_HDROP` 与
  `HTML Format`/`Rich Text Format`/`Rich Text Format Without Objects`/`PNG`）→ 其余按**三重上限**采集：
  条数 / 单项字节 / 单条目总字节，**超限跳过而非截断**（截断后的二进制是坏数据）。只做字节搬运，不解释不执行。
- **刻意不做格式名白名单猜测**（Excel / WPS / 各版本命名不一，猜错 = 功能静默不生效）——
  改用"无名排除 + 体积上限"的通用策略，任何应用的自定义格式都能覆盖。
- **模型**：`ClipboardEntry.named_formats: Vec<NamedFormat{name, data_base64}>`（`#[serde(default)]`，camelCase），
  C# 侧 `ClipboardNamedFormat`（仅承载，写回由引擎完成）。
- **写回**：`capture::write_back` 在标准格式之后、`CloseClipboard` 之前追加 `formats::write_back`
  （沿用 1302「`EmptyClipboard` 只调一次、多格式并存」骨架）；**纯文本模式不写**（用户要的就是只有文字）。
- **列表摘要剥离**：`entry_summary_json` 把 `namedFormats` 置空 —— base64 会撑爆 IPC 载荷。
- **设置**：`named-format-passthrough`(true) / `-max-count`(8) / `-max-kb`(1024) / `-total-kb`(4096)。

### P1-5 · 按应用清洗规则 —— 已实现（需人工确认交互）
- **新依赖** `regex = "1"`；**新模块** `engine/src/rules.rs`：规则 = `{app, action, pattern, replacement}`，
  `action ∈ ignore | drop | replace`。**非法正则只跳过该条并记日志**（不 panic、不丢弃整份规则）；
  规则为空 = **零行为变化**。
- **接入点**：`ignore` 在**读取剪贴板之前**判定（省一次 IO）；`drop`/`replace` 在读到快照后应用
  （`text`/`html`/`rtf` 同时替换）。规则编译缓存随 `apply_settings` 按 JSON 指纹**按需重编译**。
- **设置界面**：新增「按应用清洗规则」卡 —— 结构化编辑器（可编辑应用下拉 + 动作 + 正则 + 替换 + 删除 + 添加），
  正则**即时红框校验**（非法仍可保存，引擎会安全跳过并记日志）；存 `app-rules` JSON 数组字符串。

### P2-1 · 渐进式富文本探测 —— 已实现（需真机观测定时）
- `capture::read_snapshot_progressive`：来源命中 `RICH_TEXT_APPS`（excel/winword/powerpnt/outlook/et/wps/wpp/wpspdf）
  **且首读为纯文本**时，按 `[0,40,80,140,220,360,560]ms` 调度重读，**一旦拿到 HTML/RTF 立即返回**；
  调度耗尽返回**最后一次有效快照**（绝不因探测丢内容）。普通应用零额外延迟。

### P2-2 · 敏感信息识别 + 预览脱敏 —— 已实现（需人工确认观感）
- `privacy::detect_sensitive`：密钥 > 手机号 > 身份证 > 银行卡 > 邮箱，`OnceLock` 缓存正则。
  **刻意不用 `\b`** —— Rust 的 `\b` 是 Unicode 词边界，中文字符属 word char，
  "手机号13812345678"里的 `\b` 不成立、永远匹配不到（中文语境经典陷阱），改用"前后不是数字"的显式断言。
- 命中 → `is_sensitive=true` + 类别名追加进 `tags`（于是天然可被 `tag:手机号` 搜到，无需新搜索语法）。
- 面板：预览按 `sensitive-mask-leading/trailing`（默认 3/2）遮罩为 `前三••••后二`，并显示「敏感」危险色徽标；
  **只影响显示**，复制/粘贴仍是全文。

### P2-3 · 临时粘贴 —— 已实现（需人工确认还原时机）
- 引擎新增 `TEMP_CLIP`（存**快照**而非条目 —— 快照自带全部原始数据，还原无需落盘、无副作用）与两条命令：
  `copy_temp_to_clipboard`（快照用户原剪贴板 → 写回目标条目）、`restore_temp_clipboard`（还原 + 清空）。
- **过期保护**：快照 >10s 不再还原（用户期间可能已复制新内容，还原反而会**覆盖用户的新复制**），只清空 + 日志。
- `capture::write_back_snapshot` + `snapshot_fingerprint`：快照直写剪贴板并与写回侧共用指纹做**回环抑制**。
- 面板入口：**Ctrl+中键**（中键仍是普通"粘贴回原窗口"）；客户端 250ms 后台延迟后还原。

### P2-4 · 标签体系补全 —— 已实现（需人工确认交互）
