## 二、P0 级问题（直接解释「稳定版更差」）

### P0-1 功耗失控：休眠后风扇长转，且「修复」并未真正修复

发布包内的代码**完全没有电源事件处理**（`docs/audits/2026-09-18-power-management.md` 自述：全仓搜 `PBT_APMSUSPEND` / `PowerModeChanged` / `SessionSwitch` 零命中），同时存在永不停止的高频活动。已在发布后修复（10:43–10:48），但**当前源码仍留两个缺口**：

1. **帧率组件默认就是开启的** —— `packages/shell/shell-menu-bar/Status/MenuBarStatusStrip.cs:1191`
   ```csharp
   SetComponentVisible(btnId, settings?.Get(ext.SettingsKey, true) ?? true);  // 默认 true
   ```
   → `:1206-1209` `SetComponentVisible(Fps,true)` → `_fpsIcon.SetSampling(true)` → `:613` `CompositionTarget.Rendering += OnFrame`。
   WPF 语义：**只要存在 Rendering 订阅者，合成器就按刷新率持续出帧**，与控件是否可见无关。
   → 该审计文档自己写的验收判据「空闲不操作时 FPS 数字不再恒为 60/120/144」在默认配置下**不可能成立**。
2. **空闲淡出不联动退订** —— `packages/shell/shell-menu-bar/Windows/MenuBarWindow.cs:286-298` `SetIdleHidden` 只改 `IsHitTestVisible` / `Opacity` / 挂起 DWM 材质，**不调用 `SetSampling(false)`**。空闲淡出后（系统仍醒着）每帧订阅继续存在，只靠"组件隐藏"这一条路退订挡不住。

配套证据：菜单栏是全屏宽分层窗口 + DWM 材质，每帧代价远大于普通小窗；这与「关掉程序才停」的用户现象吻合。

### P0-2 更新链路与看门狗完全没有协调 → 更新失败 / 半更新 / 新旧混跑

- `updater/` 目录 grep `watchdog` / `pause.flag` / `stopped.flag` = **0 命中**（已核实）
- 而 `watchdog/Program.cs:149-169` 守护 `Host / Agent / Clipboard.Panel / Clipboard.Engine / Desktop`，`:110-137` 只要豁免标记不存在且进程消失，8s 宽限后**无条件拉起**
- `updater --apply` 只停 Host+Agent，且**不暂停看门狗、不写豁免标记**

后果链：更新时 Agent 被优雅停掉 → 约 8s 内被看门狗用**旧 exe** 拉回 → 等待退出必然超时失败；若替换发生在 Agent 已复活之后，磁盘上就是「新 Host/CLI/Tray + 旧 Agent」，而 Agent 单实例互斥使其无法被覆盖 → 典型混合版本。此外 **Tray / Watchdog / DesktopControl 全程未被停**，更新后仍以旧二进制运行。

### P0-3 `BetterDesktop.DesktopControl.exe` 同名短命进程 → 看门狗/Agent 判活被骗

- 托盘**已经修过这个坑**并留了注释：`tray/PipeProbe.cs:23-32`、`tray/ProcessBridge.cs:180-189` ——「桌面控制菜单是短命进程、与常驻服务**同名**，按进程名判定会误判」，故托盘改用**命名管道**判活
- 但**看门狗仍按进程名**：`watchdog/Program.cs:168` 守护 `Desktop`，`:219-235` `IsRunning` → `Process.GetProcessesByName("BetterDesktop.DesktopControl")`
- 而 CLI 确实会用同名 exe 起短命菜单进程：`BetterDesktop.Cli/HeadlessExecutor.cs:521-522` 传 `--desktop-controls`（`shell-desktop-control/Program.cs:14` 注释自称"**短命**：弹菜单 → 用户点选/关闭 → 退出"）

后果：
1. 用户弹一次桌面右键菜单 → 看门狗/Agent 误判"桌面服务在运行" → **真服务已死却不被拉起** → 自绘桌面突然消失且不自愈；
2. 每次弹菜单都造成"存在 → 消失"抖动，而 Agent 的 `HostPresenceWatcher` / `ExclusiveCapabilityHost` 依此反复装/摘桌面图标钩子与任务栏外观 → 表现为「双击切换图标要按两次」「任务栏外观闪动」。

### P0-4 注销路径静默失败 + 注册键清理不全 → 卸载后留下指向已删文件的孤儿右键项

- `packages/shell/shell-context-menu/Services/ComShellExtensionRegistrar.cs:115-141`：`public static void Unregister()`，整段包在 `try/catch` 里**只记日志、无返回值**
- `SystemIntegrationRegistrar.cs:266-274` 调它时的注释自认：「三个调用都不抛（内部各自吞并记日志），**失败面主要体现在自启项**」
- `BetterDesktop.Cli/Program.cs:141,153-158`：`ok` 只反映自启项清理 → **COM 注销失败也会 exit 0**
- `SystemIntegrationRegistrar.cs:228-242` `CleanupStaticVerbKeys` 只清 5 个静态动词，**不覆盖** `Explorer\CommandStore\shell\BetterDesktop*` 子动词与逐扩展的 `BetterDesktopConvert` / `BetterDesktopUnzip`

后果：卸载脚本以为成功，接着删除 `native\BetterDesktopShellMenu.dll`；explorer 此后**每次**文件/文件夹右键都要加载一个不存在的进程内 COM 服务器 → 右键报错/变慢/多余失效项（点击报"找不到文件"）。

## 三、P1 级问题（可感知的卡顿、失效与长期占用）

### 1. 托盘 UI 线程被同步子进程调用阻塞（最长约 46s）
- `tray/ProcessBridge.cs:422`：`var output = p.StandardOutput.ReadToEnd();` —— **`ReadToEnd` 没有超时**，其后的 `WaitForExit(15000)` 起不到保护作用（注释里"绝不无限等待"与实现不符）
- `tray/TrayApplicationContext.cs:434-448` `SendCommand`：最多 3 次 `RunCli` + `Thread.Sleep(500)`，每次 `RunCli` 内 `WaitForExit(15000)` → 最坏 ≈ 46s
- 调用点在 UI 线程（`TrayApplicationContext` 的 `Attach/Run`）

后果：托盘消息泵被冻结十数秒，「点了没反应」「托盘卡死」。同一方法被 `TrayApplicationContext.cs:789/819`（查看注册状态、注册/修复/注销）直接使用。

### 2. 剪贴板 IPC 同步调用阻塞 UI，且管道写无超时
- `shell-clipboard-ipc/ClipboardIpcClient.cs:459,470`：`WaitConnected(2s)` + `tcs.Task.Wait(_timeoutMs=5000)` → 同步阻塞调用线程最长 ≈ 7s，被 UI 路径（菜单栏按钮、打开历史、粘贴）直接消费
- `shell-clipboard-ipc/ClipboardTransport.cs:62,78-84`：`PipeOptions.None` + 阻塞 `stream.Write`，**无写超时** → 引擎不读取、管道缓冲满时工作线程永久阻塞 → 再回不到心跳/重连循环，`_connected` 仍为 true，**连接永不恢复**直到进程重启

### 3. 弹窗隐藏后定时器不停（`Hide()` 不触发 `OnClosed`）
- `shell-core/Windows/PopupWindowBase.cs:130-140`：`HidePopup()` → `Hide()`，窗口存活、`OnClosed` 不触发
- `shell-menu-bar/Windows/ControlCenterWindow.cs:806-815` 启动 2s SMTC 轮询，仅 `:1013-1021` `OnClosed` 停止，且**无 `IsVisibleChanged`** → 打开过一次控制中心后，整机生命周期每 2s 一次原生 SMTC 会话枚举
- `shell-menu-bar/Windows/CpuPanelWindow.cs:172-184` 启动 1s 定时器 + LibreHardwareMonitor，仅 `:25 / :216-219` `Closed → CloseSelf` 停止，**无 `IsVisibleChanged`** → 打开过一次 CPU 面板后每秒原生调用 + 长期持有传感器句柄

（对照组：`SoundPanelWindow` / `NetworkPanelWindow` / `MemoryPanelWindow` / `MicrophonePanelWindow` 都正确实现了 `IsVisibleChanged → Pause/Resume`。）

### 4. Dock 每秒 2 次全量窗口枚举 + 逐窗口 `OpenProcess`，且在 UI 线程、无电源门控
- `shell-dock/DockWindow.xaml.cs:90-93`（1s）、`:191`、`:379` → `:2039-2043 RefreshAll`
- → `:2049 GetRunningExecutablePaths()` + `:2088 GetRunningWindows()`，后者是 `EnumWindows` + 每个可见窗口 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`
- 对比 `_autoHideTimer`（`:453`）已接 `ShouldPauseHighFrequencyWork`，**`_refreshTimer` 没接**，dock 隐藏、系统待机时照跑

### 5. 常驻轮询普遍缺电源门控
`MenuBarStatusStrip.cs` 中 `ShouldPauseHighFrequencyWork` **仅 1 处**（`:605`，只护住 FpsIcon）：网络速率（1s，UI 线程直接 `NetworkCoreNative.ReadPrimary()`）、信号（5s）、时钟 均无门控。

### 6. 桌面排序桥无限循环读注册表
`shell-desktop/Services/DesktopBrowser.cs:53,541-551`：`while (true) { Thread.Sleep(1500); ReadExplorerSort(); }`，无取消令牌、无退出路径 → 整机生命周期每 1.5s 一次注册表读取（即使功能关闭、组件停用、系统待机）。

### 7. IPC 20ms（50Hz）常驻唤醒源
`shell-clipboard-ipc/ClipboardIpcClient.cs:198-202`、`shell-index-ipc/IndexIpcClient.cs:448-453`：`_wake.Wait(20)`，注释自陈是"常驻唤醒源"，直接妨碍 CPU 进入深空闲。

### 8. 事件订阅泄漏（累积式）
`shell-desktop/Controls/DesktopIconsControl.cs:2491-2508`：每次框选 `_rubberWatchdog.Tick += ...` 挂一个新回调，`:2515` 清理时只 `Stop()` **不减订阅** → 长会话里每框选一次多一个回调，越用越重。

### 9. 菜单命令管道单实例导致并发命令被拒、可能误报
`host/MenuCommandPipe.cs:54`：`new NamedPipeServerStream(PipeName, PipeDirection.In, 1)`；`:82` 在**持有该唯一实例期间** `await dispatch(action, path)`（弹面板/走转换耗时不定）→ 并发 CLI 转发在 `MenuCommandPipeClient.Connect(1500)` 撞 `ERROR_PIPE_BUSY` 后失败走降级，对 `NeedsHost` 类动作会**误报"需要 BetterDesktop 正在运行"**（宿主其实在跑）。
