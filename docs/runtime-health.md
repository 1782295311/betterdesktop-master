# runtime-health.md — 运行时健康规则

> 地位：程序跑起来之后的健康底线（MECHANISMS.md M10）。这些是老仓血泪最集中的区域，全部移植为规则。

## 一、日志：单一管道

1. 全仓只有一条日志管道（内核 Logger 服务 + 统一输出目录）。
2. 禁止 `Console.WriteLine` / `Debug.WriteLine` / `Trace` / 自写日志文件；业务代码一律经内核日志服务。
3. 日志分级规范（Debug/Info/Warn/Error）与结构化字段约定 P1 随内核冻结。

## 二、崩溃可见：三个入口

1. 全局异常收口三入口：`AppDomain.UnhandledException` + `TaskScheduler.UnobservedTaskException` + WPF `DispatcherUnhandledException`。
2. 禁止吞异常（`catch {}`）；后台线程异常不得静默消失；用户必须得到可见提示。
3. 崩溃即诊断：崩溃信息落日志并携带模块/版本上下文（对应老仓「十分钟定位到哪次降级」的判据）。

## 三、启动自检：Fail-Fast

依赖缺失、关键服务装配失败一律响亮失败（启动自检 + 明确报错），禁止静默启动半残状态。

## 四、降级上报：显式化

1. 能力不可用必须走降级上报（`DegradationNotice` 四字段非空：来源/能力/消息/时间）。
2. 禁止静默降级（catch 后返回空实现不报告）、禁止同名 `Mock*` 顶替真实现而不上报。
3. 降级必须用户可见或日志可见（P2 起进健康检查面板）。

## 五、Fail-Closed 守卫

任意「是否放行」判定默认拒绝：`Ensure*` / `Guard*` / `Require*` 类方法未满足条件必须抛或拒绝，禁止默认放行。

## 六、超时、重试与资源上限

1. 一切 IPC / 网络 / 跨进程调用必须有超时；超时策略全局统一（P1 冻结）。
2. 后台任务有数量与内存上限；禁止无界队列与失控线程。
3. 重试必须有退避且总次数有界。

## 七、健康检查

P2 落地诊断入口（`better-desktop doctor` 或同等物）：一键输出版本、门禁状态、降级清单、资源占用。
