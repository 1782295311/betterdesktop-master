# reuse-rules.md — 功能复用与反臃肿规则

> 地位：防止程序臃肿的结构性规则（MECHANISMS.md M7 的唯一真相源）。与 coding-standards.md 的分工：本文件管「什么该复用、什么该拆包、什么禁止复制」，coding-standards 管「单个代码文件怎么写」。

## 原则一 · 单一实现

一个能力在仓库内**只有一处实现**，其余一律引用。发现同义实现（两份降级上报、两套时钟逻辑……）即视为技术债，按老仓教训处置：收敛到单一来源并迁移全部调用方。

## 原则二 · 共享层上移

可复用的东西必须上移，不允许停在消费方：通用逻辑 → kernel/common（P1）；UI 资产 → shell-foundation（P2）；跨包契约 → 对应 Contracts。**下不沉、上不落**。

## 原则三 · 包粒度判据

新增代码前先回答：是「新包」「新插件」还是「并入既有包」？

| 判据 | 结论 |
|---|---|
| 独立部署 / 独立卸载 / 独立生命周期 | 新包（或独立插件） |
| 仅是本包内部实现细节 | 并入既有包 |
| 是一个功能切片的用户可见能力 | 新插件（走内核 Plugin 通道） |
| 与既有包强耦合、同生命周期 | 并入，不得硬拆 |

反臃肿红线：单个包公共类型超过 80 个、或单方法超过 60 行，必须在评审中说明拆分计划。

## 原则四 · 禁止复制粘贴

1. 复制代码 = 登记技术债；确需参考旧仓行为时**重写**，不得复制（ADR-001 R5 已冻结旧仓侧）。
2. 仓库内部跨包复制一律禁止；要复用就把代码上移并引用。
3. P1 落地机检 `verify-code-duplication.ps1`：去注释与字符串字面量后做规范化骨架比对（老仓已有成熟脚本经验可重写移植）。

## 原则五 · 依赖方向单向

包间依赖严格沿分层单向（kernel → shell → host），循环依赖零容忍。P1 起由架构测试机检，违规新增一条即红（棘轮冻结存量）。

## 原则六 · 能力收敛

同名/近义能力只能有一个（注册进 MECHANISMS.md）；发现第二套即按注册表流程裁决，禁止并存。

## 机检状态（诚实标注）

| 规则 | 当前机检 | 规划机检 |
|---|---|---|
| 复制粘贴检测 | **暂无机检**（靠评审） | P1：`verify-code-duplication.ps1` |
| 包间依赖方向 | **暂无机检** | P1：架构测试（含棘轮） |
| 包粒度判据 | **暂无机检** | P1：包登记表 + gen --check |
| 单一实现（能力收敛） | MECHANISMS 登记制 + 评审 | 随上三条联动 |
