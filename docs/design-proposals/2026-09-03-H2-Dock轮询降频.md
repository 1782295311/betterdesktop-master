# H2 · Dock 60ms 常驻 tick 降频（双档自适应）

> Wave 2 资源卫生 · 设计方案。2026-09-03。A/B 门槛单测：`DockTickPolicyTests`（shell-dock-tests）。

## 测量（治理前）
`DockWindow._autoHideTimer` 固定 60ms，构造即 `Start()` **永不停表**：
- UI 线程每秒被唤醒 ≈**16.7 次**，每小时 60,000 次；
- 每 tick P/Invoke：`ShouldHideOnFullscreen`（前台窗口/显示器查询）+ `GetCursorPos` + DPI 换算 + `IsCursorOverDock` + `ShouldShowOnEdgeHover`（布局查询）+ `GetLastInputInfo`；
- 而绝大多数 tick 的裁决结果 = "维持现状"（`SetDockVisible` 状态机短路，纯空转）。

tick 的五项职责对延迟的真实需求并不相同：空闲隐藏（分钟级）、全屏隐藏（百毫秒级无感知）、
贴边/悬停唤出（唯一 ≤60ms 级的交互需求）。

## 设计方案：双档自适应（纯函数策略 + tick 尾部落档）
`DockTickPolicy.NextIntervalMs(statePending, cursorNearDock)`（纯函数，可单测）：
- **快档 60ms**：dock 隐藏等待唤出（statePending）或光标进入预唤出带；
- **慢档 250ms**：其余一切（常驻显示确认、用户活跃、全屏稳定态）。

`DockWindow` 接线（`ApplyTickInterval`）：
- 仅档位变化时写 `Interval`（每拍赋值会重置 DispatcherTimer 相位，以 `_tickFast` 字段去抖）；
- **预唤出带** `IsCursorNearSummonBand`：dock 底部矩形外扩 3×高/1×宽（逻辑坐标）；dock 隐藏后
  Top/Left/Actual* 仍保留上次数值，几何判定在隐藏态继续有效——这是"隐藏态靠带判定提前升档"的前提；
- 全屏稳定态（已隐藏+光标远离）归慢档：全屏→恢复的显示延迟最坏 ≈250ms，无感知。
