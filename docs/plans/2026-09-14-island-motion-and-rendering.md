# 灵动岛动效与渲染规格（2026-09-14）

> 用户需求（2026-09-14 拍板）："灵动岛的 UI 非常灵动，收入收出像水滴一样丝滑，还能像水一样融入菜单栏；进度条是脉冲式的，中间是百分比的进度；整体十分现代化和科技化，不能像老大爷一样僵硬。"
> 地位：本文件是 [2026-09-14-dynamic-island.md](2026-09-14-dynamic-island.md) 的渲染与动效规格（该文档 §1 的结论以本文件为准）。
> 状态（2026-09-16）：§4 弹簧参数表、§5 脉冲进度、§7 降级档、§8 性能口径、§9 红线已由 [2026-09-16-island-surface.md](2026-09-16-island-surface.md) 落地；
> §2 的 DComp + HLSL metaball 自渲染档仍待"是否引入互操作库"拍板（当前用解析几何构造同一形态语义的轮廓，替换面仅限绘制）。

## 0. 结论摘要

语言仍是 C# / .NET 8，**但岛的动画层不走 WPF 视觉树**：岛使用"无重定向位图窗口 + DirectComposition 交换链"自渲染，液体效果用 D3D11 的 SDF metaball 像素着色器绘制，文字/图标/进度用 D2D/DWrite 在同一交换链内绘制；需要滚动列表等复杂交互时，展开态下挂既有 WPF 弹层（复用 `MenuBarPopupWindow` 基座），把动画层与交互层解耦。

## 1. 为什么 WPF 视觉树达不到这个效果（三条硬约束）

| 约束 | 证据 | 后果 |
|---|---|---|
| 窗口是分层窗口 | `packages/shell/shell-core/Surface/ShellWindow.cs:79`（`AllowsTransparencyDefault => true`）、`packages/shell/shell-core/Windows/PopupWindowBase.cs:50`（`AllowsTransparency = true`） | WPF 分层窗口的内容走软件合成路径；逐帧模糊/位图特效的 CPU 成本与每帧位图搬运无法支撑 120 Hz |
| WPF 无阈值化滤镜 | 全仓 `ShaderEffect` / `.fx` / `.hlsl` 命中共 0 | 经典的"液体/粘连"效果依赖"模糊 + 阈值化（对比度抬升）"或 SDF，WPF 只有 `BlurEffect`，无法阈值化，做不出颈部 |
| DWM 材质在分层窗口下失效 | `packages/shell/shell-core/Vibrancy/DwmHelper.cs:148`（"`AllowsTransparency=true` 会被 DWM 忽略 backdrop"） | "像水一样融入菜单栏"不能靠 Mica/Acrylic 材质对齐，必须在自己的合成面上精确绘制颜色与模糊等级，与菜单栏保持一致 |

补充事实：全仓无 `D3DImage` / `IDComposition` / `Vortice` / ANGLE 使用先例；`SkiaSharp 2.88.9` 仅被 `packages/shell/shell-convert/BetterDesktop.Shell.Convert.csproj` 用于图像格式转换（CPU 路径），不是渲染底座。

## 2. 渲染架构

```
岛窗口（WS_EX_NOREDIRECTIONBITMAP + WS_EX_NOACTIVATE + WS_EX_TOOLWINDOW）
  ├─ DirectComposition 目标 → 交换链视觉（D3D11）
  │     ├─ 液体层：SDF metaball 像素着色器（HLSL）→ 胶囊/颈部/融入菜单栏
  │     ├─ 内容层：D2D + DWrite（标题、图标、脉冲进度、百分比数字）
  │     └─ 高光/描边/内发光：同一着色器内的第二遍或 D2D 图层
  └─ 命中测试：仅可视区域（不可见处 HTTRANSPARENT）

展开态需要列表/按钮等复杂交互时：
  岛本体保持自渲染（形变仍逐帧）
  下挂 WPF 弹层（MenuBarPopupWindow 族）承载列表与交互，不参与 120 Hz 形变
```

| 依赖选项 | 评价 |
|---|---|
| Vortice.Windows（MIT） | D3D11 / DXGI / D2D / DComp / DWrite 一套齐备，社区维护活跃；**推荐**（自造绑定层的工作量与风险都更高） |
| 手写 COM 互操作 | 结果等价，但需自声明 `ID3D11Device`/`IDXGISwapChain`/`ID2D1Factory1`/`IDCompositionVisual`/`IDWriteFactory` 等大量接口；只有"零新增第三方依赖"是硬要求时才选 |
| SkiaSharp GPU | 其 WPF GPU 面经 ANGLE（OpenGL ES 转译），与分层窗口限制冲突，且 Skia 无 D3D 后端；**不作为主路径**，仅作为降级档的 CPU 渲染 |
| WinUI 3 / Microsoft.UI.Composition | 能力合适，但引入第二套 UI 框架与 Windows App SDK 依赖，与 [../MECHANISMS.md](../MECHANISMS.md) M6"单一 UI 地基"冲突；且为一个小表面换栈不划算。**不采用** |

不采用 WinUI 3 后，M6 的边界需要在机制注册表里写清：**自绘动画表面全仓仅此一处**，其颜色与字体令牌仍从 `IAppearanceService` 读取，不产生第二套主题源；其余 UI 一律留在 WPF。

### 2.1 语言选择：为什么是 C#，而不是 Rust/C++

岛"以视觉为主、不承担功能"这一点，恰恰意味着**语言不影响它的像素成本，只影响它的集成成本**——而同进程集成正是这个组件的全部难度所在。

| 判断 | 依据 |
|---|---|
| 像素成本与语言无关 | 真正逐像素干活的是 GPU 上的 HLSL 着色器；C# 只做每帧编排（更新几个参数、提交一次呈现），量级是微秒，不是瓶颈 |
| 必须与菜单栏同进程 | "像水一样融入菜单栏"要求同一几何来源、同一主题令牌、同一时刻的合成。跨进程要复制菜单栏几何/颜色/模糊档并保持逐帧同步，**1 帧延迟就会在接缝上露馅**——而这个效果的全部卖点就是没有接缝 |
| 同进程即 C# | 壳是 C#；岛要与 `IActivityService`、`IAppearanceService`、菜单栏窗口与弹层直接协作，同进程同语言是零成本 |
| 既有跨语言纪律不适用 | [../MECHANISMS.md](../MECHANISMS.md) M17 的"独立进程 + 命名管道"用于**数据面**（剪贴板/索引/转换）；岛是逐帧对齐的**视觉面**，属反例 |
| 另起进程/换语言的代价 | Rust 或 C++ 独立进程需要重建：窗口类 + DComp + D2D/DWrite 文本 + 命中测试 + DPI/IME + 主题令牌复制 + 活动 IPC + 菜单栏几何同步 + 壳在场生命周期——全部为 0 像素收益 |
| 唯一的换语言理由 | 若将来要"每屏一个岛、且壳退出后岛仍存在"，那才是独立进程的候选题；它与"融入菜单栏"当前需求直接冲突 |

结论写明：**语言 = C# / .NET 8；着色器 = HLSL（几百行，属渲染资产不属第二套程序）；绘制 API = D2D/DWrite（经互操作库）**。

### 2.2 菜单栏的对应改造：分层推进，不整体重写

前提澄清："融合菜单栏"**不要求菜单栏也自渲染**——岛只需要菜单栏的**下沿几何、模糊档与主题令牌**作为输入，就能把菜单栏下沿作为大球体参与 SDF 融合。因此菜单栏改造按"先立后破"分期，不做整体重写。

"写死在 C# 上"的真正来源不是语言，而是内容契约：`packages/api/Core/IMenuBarExtension.cs:17` 的 `GetVisual()` 返回 WPF `FrameworkElement`，所以每个菜单栏条目天然是一个 C# 视觉元素。要解除这个绑定，改的是契约，不是语言。

| 期 | 内容 | 收益 | 代价 |
|---|---|---|---|
| S1（随岛） | 菜单栏暴露内部度量契约（下沿几何、模糊档、主题令牌），岛据此做融合；弹层与岛互斥 | 接缝不可见，够用 | 一个内部契约，零 UI 改动 |
| S2 | 新增**声明式条目模型**（图标 + 文本 + 命令 + 锚点）；新条目用它渲染，既有 `GetVisual()` 扩展原样保留 | 条目不再写死为 WPF 元素，两种渲染后端都能画；主题/DPI/动效统一 | 契约新增（非破坏） |
| S3 | 菜单栏 chrome（背景、分隔、悬停高亮、弹层进场）纳入自渲染层，内容仍由 WPF 承载 | 菜单栏与岛共用同一视觉语言 | 需先解决"同窗两套合成"问题（见红线） |
| S4（可选） | 菜单栏整体自渲染（含文本与命中测试） | 形变自由度最高 | 需重写全部扩展视觉与交互；收益低于成本 |

红线：

- **禁止**在未解决同步的前提下让"动画面"与"内容面"分属两个窗口：两个独立时钟必然出现 1 帧错位，而融合效果最怕错位。
- **禁止**为菜单栏再造一套控件体系：S3/S4 若不能复用既有控件（滑块、开关、列表、弹层基座），就不做。
- S4 仅在"S3 稳定运行且确有形变需求驱动"时启动，且必须先有 S3 的真机帧预算数据。

## 3. 液体形态的数学规格

用 metaball（等值面）而不是路径动画，才能得到"表面张力"的颈部与融合：

```
对每个球体 i：d_i = length(p - c_i) - r_i
合并：D = smin(d_1, d_2, ..., k)         // 多项式平滑最小值，k = 平滑系数（表面张力）
       smin(a, b, k) = -k * log(exp(-a/k) + exp(-b/k))    // 或多项式近似避免 exp 开销
覆盖：alpha = smoothstep(0, w, -D)        // w = 边缘羽化宽度（亚像素级抗锯齿）
```

| 参数 | 作用 | 建议区间 |
|---|---|---|
| `k`（平滑/张力） | 决定"粘连"程度；越大越像同一片水 | 4–12 px（按 DPI 缩放） |
| 颈部半径 | 胶囊与菜单栏接触处的可见连接粗细 | 2–6 px |
| 断裂阈值 | 距离超过此值颈部断开（"水滴脱离") | 8–16 px |
| 边缘羽化 `w` | 抗锯齿与"水面感" | 0.75–1.5 px（DIP） |
| 球体集合 | 胶囊本体（圆角矩形 SDF）+ 菜单栏下沿（长条 SDF）+ 目标位置的"亲和球" | 3–5 个 |

融入菜单栏的实现：岛在收起态与菜单栏下沿**共享同一条 SDF 边界**（菜单栏下沿作为大球体的一部分参与 smin），因此视觉上是"从菜单栏里长出来"而不是"贴在下面"；离去时颈部先变细再断裂回缩。

## 4. 动效规格（弹簧物理，不是线性缓动）

| 状态转移 | 曲线 | 时长 | 备注 |
|---|---|---|---|
| 菜单栏 → 胶囊（收入） | 临界阻尼弹簧（无回弹，丝滑） | 220–280 ms | 颈部从宽到无 |
| 胶囊 → 菜单栏（收出/融入） | 临界阻尼 + 末段加速吸附 | 180–240 ms | 末端"被吸走"的手感 |
| 胶囊 → 展开 | 欠阻尼弹簧（轻微回弹，灵动） | 320–420 ms | 回弹幅度 ≤6% |
| 展开 → 胶囊 | 临界阻尼 | 200–260 ms | 内容先淡出，再形变 |
| 通知进入 | 从菜单栏下沿"渗出" | 200–260 ms | 不用缩放出现 |
| 通知退出 | 形变收缩 + 淡出 | 160–220 ms | 不残留描边 |
| 按序粘贴计数步进 | 数字滚动 + 胶囊轻微"呼吸" | 120–180 ms | 每步都反馈，但不闪 |

弹簧参数化（实施时统一在渲染层内，禁止各处硬编码）：`omega`（频率）与 `zeta`（阻尼比）；收入与收出用 `zeta = 1.0`（临界），展开用 `zeta = 0.7–0.8`。所有动画由渲染层自己的时钟驱动，**不使用 WPF Storyboard**（分层窗口下的 Storyboard 仍会走软件路径且无法驱动着色器参数）。

## 5. 脉冲进度条规格

| 要素 | 规格 |
|---|---|
| 形态 | 环形（默认）或胶囊内横向条；环形中心显示百分比数字 |
| 脉冲 | 亮度/内发光强度的正弦叠加 + 半径 ±1.5% 的呼吸；**频率与进度解耦**（进度慢时也保持生命感，建议 1.2–1.8 Hz） |
| 进度映射 | 弧长按进度线性映射；未完成段保留低亮度"轨迹"（科技感） |
| 不确定进度 | 改用旋转扫描 + 双脉冲，不显示假百分比（与既有"禁止假精确"纪律一致） |
| 数字 | DWrite 绘制，**等宽数字（tabular figures）** 防跳动；百分比变化做短滚动而非跳变；字号随胶囊高度缩放 |
| 终态 | 完成时脉冲收敛为一次"脉冲爆发"（+ 轻微色相偏移），失败时改用警示色 + 单次抖动（不做循环闪烁） |
| 可读性 | 百分比在任何壁纸下可读：文字带 1px 描边或内阴影，不依赖背景亮度 |

## 6. 材质与"科技感"细节（按重要度）

1. **与菜单栏一致的底色与模糊等级**：从 `IAppearanceService` 取当前主题令牌与模糊档，渲染层按同一参数绘制（保证"融入"不是视觉巧合）。
2. **高光**：上边缘 1px 渐变高光（模拟水面反光），强度随形变速度微增。
3. **内发光**：展开时边缘内发光增强，收起时归零。
4. **描边**：亚像素描边，深色主题下用低对比亮边，避免"贴纸感"。
5. **噪点/颗粒**：极低强度（≤2%）颗粒可消除大面积渐变的色带；开启"精简动效"时关闭。
6. **慎用**：粒子、镜头光晕、彩虹渐变——容易从"科技感"滑向"炫技"，默认关闭或仅作为可选主题。

## 7. 降级矩阵（可靠优先于炫技）

| 环境 | 渲染档 | 效果 |
|---|---|---|
| 正常桌面（DComp + D3D11 可用） | 完整 | 液体形变 + 脉冲进度 + 高光内发光，120 Hz |
| 远程桌面 / 虚拟机会话 / GPU 驱动异常 | CPU Skia | 几何形变（圆角矩形插值）+ 内容交叉淡入，60 Hz，无颈部 |
| 系统"播放动画"关闭 或 用户选"精简动效" | 瞬切 | 无动画，状态直接切换 |
| 渲染层崩溃 | 兜底 | 岛隐藏并记一次诊断，**不得带走壳进程**（渲染线程异常隔离） |

三档动效强度由设置项控制（完整 / 精简 / 关闭），并默认尊重系统 `UISettings.AnimationsEnabled`。

## 8. 性能预算与验收

| 指标 | 预算 | 测量 |
|---|---|---|
| 形变期间帧时间 | p95 ≤ 8 ms（120 Hz）/ ≤ 16 ms（60 Hz） | 渲染层自带计时，真机取 300 帧分布 |
| 稳态空闲 | 零重绘（无动画不提交新帧） | 空闲 5 分钟 GPU/CPU 采样 |
| 每次状态转移的 GPU 提交 | ≤ 1 次交换链呈现（避免多层重复合成） | 帧调试器或自计 |
| 内存 | 渲染层常驻 ≤ 24 MB（含交换链缓冲） | 进程内存采样 |
| 视觉走查 | 颈部形变连续、无跳变、无黑边/白边、无锯齿、菜单栏接缝不可见 | 240 fps 慢放录屏逐帧检查，留证 |

## 9. 红线

- **不牺牲可读性**：任何形态下百分比、标题、图标必须清晰；动画中不得出现内容被裁切。
- **不牺牲可用性**：动画期间命中区域必须与可视区域一致（不能出现"看得见点不到"）；全屏/游戏抑制与只读态穿透规则照旧（见岛文档 §7）。
- **不在动画路径上做分配与布局**：每帧不 new、不进 WPF 布局、不查配置。
- **不引入第二套 UI 框架**：自绘只限岛这一个表面。
- **单一实现**：全仓只此一处自绘动画表面，登记进 [../MECHANISMS.md](../MECHANISMS.md)，禁止其他包再开一套。
- **不做**：粒子/光晕炫技（除非作为可选主题）、跟随鼠标的视差、与系统主题无关的强制配色。

## 10. 实现顺序

1. 自渲染骨架：无重定向位图窗口 + DComp 交换链 + D2D/DWrite 文本（先画静态胶囊，验证透明与命中测试）。
2. 液体层：SDF metaball 着色器 + 参数化（张力/颈部/羽化），静态参数下先保证形态正确。
3. 动效：自有时钟 + 弹簧积分 + 状态转移表；与 `IActivityService` 的状态机对接。
4. 脉冲进度与百分比数字。
5. 融入菜单栏：与菜单栏几何/颜色对齐（菜单栏下沿参与 SDF）。
6. 降级矩阵三档 + 设置项 + 无障碍。
7. 帧预算门禁与真机慢放走查。
