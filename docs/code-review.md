# code-review.md — 代码评审规范

> 地位：机器门禁之外的第二道闸（MECHANISMS.md M15）。原则：**机器拦得住的靠门禁，机器拦不住或不该拦的靠评审**。

## 一、评审检查单（每次 PR 逐项过）

1. 门禁全绿（`run-gates.ps1` exit 0），改门禁则变红物证齐备。
2. 决策记录齐备：非平凡决策已落 `.agents/notes/`；涉及机制/红线已登记或已开 ADR。
3. 规范符合性逐域速查：代码 → coding-standards（含并发纪律）；UI → ui-foundation；复用 → reuse-rules；插件 → extension-rules + pluginization；安全 → security；测试 → testing。
4. 红线复查：ADR-001 七条红线无触线；旧仓零复制（M4 白名单外）；无 `[Obsolete]` 垫片；无隐式扩展点。
5. 变更最小化：无顺手改动、无夹带文件。
6. 物证可信：取证环境满足 E1–E4。

## 二、合入门槛

1. 至少一次**作者以外的独立评审**；门禁 + 评审双通过才可合入。
2. main 受保护：禁止直接 push、禁止 force push（AGENTS.md 变更纪律已冻结）。
3. 争议裁决：规则冲突 → 以最新 ADR 为准；ADR 无规定 → 先落决策记录再合入；评审者与作者僵持 → 主理人裁决，裁决本身落决策记录。

## 三、评审责任

1. 评审者**默认拒绝对「规则空白处的自由发挥」放行**——规则空白应引导作者补决策记录，而不是默默合入。
2. 评审留痕：合入 PR 的描述引用决策记录编号与门禁输出（P2 起由 PR 模板机检）。
3. 评审者与作者同负物证之责：采信了不合格物证的评审，与伪证同责。
