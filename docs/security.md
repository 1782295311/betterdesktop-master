# security.md — 安全与供应链规则

> 地位：安全相关的唯一真相源（MECHANISMS.md M11）。目标形态是社区生态（第三方插件），安全不是可选功能。

## 一、插件最小权限

1. 第三方插件默认权限最小（fail-closed）：文件、网络、进程能力按声明授权，未声明即拒绝（P1 契约、P2 运行时）。
2. 危险 API（任意代码执行、进程启动、原始网络）必须有白名单与审批路径。
3. 不可信 / 重资源插件走进程外隔离（P2），进程内插件崩溃不得拖垮外壳（内核 PluginGuard，P1）。

## 二、依赖与供应链

1. 依赖最小化（reuse-rules 已冻结内核零第三方依赖原则）；新增依赖须决策记录说明理由。
2. 依赖锁定文件入库；P1 起 CI 跑 `dotnet list package --vulnerable`，有漏洞即红。
3. 第三方代码 vendoring 必须先登记（来源/版本/许可证/改动），禁止裸拷。

## 三、许可证合规

1. 每个第三方依赖的许可证必须可分发（发布物附 `THIRD_PARTY_NOTICES`，P2 起生成器维护）。
2. 传染性许可证（GPL 等）与闭源发布冲突时一票否决，走决策记录裁决。

## 四、敏感信息

1. 密钥 / 令牌 / 密码一律不入库、不入日志；设置中的敏感项加密存储（P2）。
2. P2 落地 `verify-secrets.ps1`（提交前扫描常见密钥模式）。

## 五、更新机制

发布更新包必须签名校验；更新通道可回退（P2 落地，参照 WinSparkle 的签名实践但不复制其代码）。

## 机检状态（诚实标注）

|---|---|---|
| 依赖漏洞 | **暂无机检** | P1：CI `dotnet list package --vulnerable` |
| 敏感信息扫描 | **暂无机检** | P2：`verify-secrets.ps1` |
