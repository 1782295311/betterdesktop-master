# ai-control.md — AI 控制面规范（程序功能的 AI 入口）

> 地位：AI 控制程序功能的唯一规范（MECHANISMS.md M16）。目标：让 AI（内置助手 / 第三方 Agent）能**安全、可观测、可撤销**地调用 shell 能力——像 DSH 的 tool catalog 之于 Agent 一样。
> 根本原则：**AI 是「带权限系统的用户」，不是 root**；AI 是可选增强，AI 不可用时 shell 必须完整可用。

## 一、能力目录（唯一注册处）

1. 一切可被 AI 调用的能力必须登记进**能力目录**：`id`、描述、参数 schema、效果（是否可撤销）、权限等级、超时。
2. 登记复用插件/服务通道（M5 单一机制）：能力 = 内核服务 / 命令 + 元数据，**不另建第二套注册表**。
3. 目录由内核自动生成（P2 起 `gen-capability-catalog --check`，与源码不一致即红）。
4. 未登记能力 AI 不可见、不可调（默认拒绝，fail-closed）。

## 二、入口形态（三档，同一能力模型）

1. 内核级 API：`IAiControlPlane`（进程内，供内置助手）。
2. 本地命令：`better-desktop ai <capability> --params ...`（脚本与自动化）。
3. 网络协议：本地回环 MCP server（社区标准，供第三方 Agent 接入）；只绑 `127.0.0.1` + 随机会话令牌，**禁止默认对外网暴露**。

## 三、权限分级与人在环（human-in-the-loop）

| 等级 | 例子 | 处置 |
|---|---|---|
| L0 只读 | 窗口列表、主题读取、状态查询 | 默认放行（仍入审计） |
| L1 常规 | 切换主题、打开/关闭窗口、启动应用 | AI 身份可执行 |
| L2 敏感 | 文件删除、设置修改、热键改绑 | 用户确认后执行 |
| L3 高危 | 插件安装、进程启动、破坏性迁移 | AI 默认禁止；仅人类路径或显式双确认 |

1. 每条能力在目录中声明权限等级；AI 身份（内置助手 vs 第三方）有不同默认权限；越级调用必须用户确认。
2. AI 调用与插件同受 `docs/security.md` 约束（输入钩子、网络、文件、主题包等同级待遇）。

## 四、可观测、可审计、可撤销

1. 每次 AI 调用落审计日志（谁 / 何时 / 能力 / 参数 / 结果）——走 runtime-health 日志管道，禁止旁路。
2. 可撤销能力必须支持撤销（命令系统预留 Undo 语义）；不可撤销能力必须在目录中标注并强制确认。
3. AI 活动对用户可见：状态中心显示「AI 正在做什么」，防「鬼手」效应（用户不知道谁动了桌面）。

## 五、防失控

1. 速率限制与调用配额；单次调用超时上限。
2. 禁止递归：AI 调用引发的插件行为不得再回调 AI 入口（防循环放大）。
3. 降级：AI 控制面整体可停用；停用后所有人类路径照常可用（AI 永不成为 shell 的依赖）。

## 六、验收判据（P2/P3，物证制）

1. 目录演练：目录与实际能力一致（gen --check 红证）。
2. 越级演练：未确认的 L2 调用被拦、L3 被拒（物证）。
3. 审计演练：任意调用可完整回溯（物证）。
4. 停用演练：AI 控制面停用后 shell 全功能可用（物证）。
