# Agent Note: 会话交接增强——让无记忆的新会话能照章接手

Status: implemented — 2026-08-19，P0 验收后首轮增强

## Problem

评估「另一个 AI 会话能否照仓库规则继续写下去」时发现四个缺口：其一，没有「当前阶段与下一步」的交接指针，新会话读完 AGENTS 仍不知道项目进行到哪、下一步做什么；其二，仓库文档未规定唯一合法解释器，而 Windows PowerShell 5.1 会把仓库内 UTF-8 无 BOM 脚本读成乱码（本会话已实测踩坑），新会话按惯性用 `powershell` 会直接卡在门禁解析错误上；其三，P1 的 C# 代码编写规则完全缺失（无 coding-standards、无术语表），新会话写内核代码只能自由发挥；其四，部分文档规则只有纸面没有门禁——「一段一行物理行」无检查、「门禁注册一致性」无检查，属老仓 ADR-001 点名的「假绿」失败模式。

## Decision

落地六项增强，全部与既有机制同构、不新增机制种类：

1. 新增 `docs/architecture/STATUS.md`：当前阶段 / HEAD / 下一步 / 交接与收工检查清单，作为新会话接手第一入口。
2. 新增 `docs/cookbook/会话交接.md`：冷启动五步标准流程（读状态→确认基线→查决策→三问→收工）。
3. 新增 `docs/TERMINOLOGY.md`：核心术语表（含「Fiber 不得译作纤程」等纠偏项）与目录↔命名空间映射，命名唯一真相源提前到 P0 落地。
4. 新增 `docs/coding-standards.md`：P1 代码基线（net8.0-windows / nullable / warnaserror）与内核八条禁止清单。
5. 强化 `AGENTS.md`：门禁纪律写入「唯一合法解释器 PowerShell 7 与全量检查命令」；新增「会话交接」段；文档纪律指向 coding-standards 与 TERMINOLOGY。
6. 新增两道门禁并登记：`verify-md-wrap`（散文段落一段一行，替代纸面规则）与 `verify-gate-registry`（verify 脚本必须登记 + 每道门禁必须有变红物证，防门禁静默失联）；两道均需变红物证。
7. `AGENTS.md` 字数预算由 900 放宽至 1100：新增交接段与门禁纪律内容已逼近上限，且 P1 阶段本文件仍会小幅增长；放宽理由即本记录。

## Alternatives considered

- 只靠本次会话记忆交接，不落盘：否决——记忆不随会话转移，与「双重纠错」的机器对齐原则相悖。
- 把交接流程全部塞进 AGENTS.md：否决——AGENTS 受字数预算约束，流程细节放 cookbook、指针放 STATUS，各归其位。
- 不新增门禁、只补文档：否决——「规则无门禁即假绿」是老仓血泪教训（ADR-001 B1），硬换行与门禁注册这两条完全可机检，必须机检。
- 用真实无上下文会话实测后再决定增强内容：已并行执行（实测报告另见会话记录），本记录与实测结论合并落地。

## Consequences

- 门禁总数由 5 道增至 7 道；新会话冷启动成本收敛为「读 STATUS + 跑一次全量门禁」。
- `verify-gate-registry` 使「新增 verify 脚本但忘记登记」从静默假绿变为立刻变红。
- 术语表与代码规范先于 P1 代码存在，符合红线 R1「门禁先于业务」的同一逻辑：规则先于代码。
- 后续维护义务：STATUS.md 必须在每阶段结束时更新；coding-standards 的禁止清单在 P1 落地对应护栏后逐条标注机检状态。
