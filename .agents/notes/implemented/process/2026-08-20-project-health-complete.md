# Agent Note: 项目健康规则补全——测试/运行时/安全/构建/质量五域一次定齐

Status: implemented — 2026-08-20，用户要求「与其做屎山，不如现在定好框架与规则」

## Problem

用户此前点出的坑（统一字体/窗口属性、功能复用、扩展性）已由 M6–M8 覆盖，但用户明确要求**主动发现并补充其余所有对项目健康有益的规则**，而不是等踩坑后再补。逐域盘点后发现五大类完全空白：测试与取证策略、运行时健康（日志/崩溃/降级——老仓血泪最集中的区域）、安全与供应链（社区生态前提）、构建与发布（可复现/门禁/版本）、产品质量（性能/可访问性/本地化/数据迁移）。另外 `docs/cookbook/会话交接.md` 引用了一个尚不存在的 `docs/architecture/环境陷阱.md`，属于悬空引用。

## Decision

1. 新增五份规范并登记 M9–M13：`docs/testing.md`（测试金字塔/契约优先/禁 --no-build/flaky 处置/性能基准）、`docs/runtime-health.md`（日志单管道/崩溃三入口/启动自检 fail-fast/降级上报/fail-closed 守卫/超时与资源上限）、`docs/security.md`（插件最小权限/依赖锁定与漏洞扫描/许可证合规/敏感信息/更新签名）、`docs/build-release.md`（SemVer 单一来源/SDK 锁定/发布门禁/CHANGELOG/插件禁 AOT）、`docs/product-quality.md`（性能预算/可访问性/本地化/设置单一来源与 schema 迁移/隐私）。
2. 新建 `docs/architecture/环境陷阱.md`：登记本会话与老仓已踩实坑 6 条（pwsh 5.1 乱码、git 空目录、取证误打包、脚本块作用域、CRLF、git show 路径）+ P1 预告坑 3 条，并规定「每踩一个新坑必须登记」。
3. `AGENTS.md` 文档纪律第 5 条改为十份规范的统一索引（单点取用，防文档失散）。
4. 所有新规则**逐条诚实标注机检状态**：现在没有代码可检的规则一律写「暂无机检（靠评审）+ 规划机检」，机检随 P1/P2 代码落地，绝不放空转门禁制造假绿。
5. 字数预算调整：`MECHANISMS.md` 上限由 900 放宽至 1400（M9–M13 五域登记行所致）；新增五份规范与 `环境陷阱.md` 的预算条目。

## Alternatives considered

- 合并成一份「健康规则大全」：否决——单一巨文档无人精读，且与 DSH「解释性文档压到离代码最近的一层」原则相悖；分域文档各归其位，AGENTS 索引统一入口。
- 现在就为五域上机检：否决——无代码可检，空转门禁只会制造「规则已生效」的错觉（假绿是老仓第一号失败模式）。
- 只登记 MECHANISMS 不写规范文档：否决——注册表只回答「选哪套」，规范文档才回答「怎么做」，两者必须同存（ADR-001 F5 双向对齐义务的同构）。

## Consequences

- 规则框架在 P1 开工前闭环：宪法（红线）→ 机制（M1–M13）→ 十份分域规范 → 7 道门禁机器对齐。
- P1/P2 验收判据扩充为三组机检计划（测试覆盖棘轮/日志与吞异常扫描/依赖漏洞），与「每阶段可运行」红线并列。
- 维护义务：环境陷阱登记制是活文档；新增规范必须同步登记 MECHANISMS 并更新 AGENTS 索引，否则视为未落地。
