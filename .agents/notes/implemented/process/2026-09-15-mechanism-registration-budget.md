# Agent Note: 剩余功能批次机制登记与 MECHANISMS 预算调整

Status: implemented

## Problem

剩余功能批次（P0→P5 索引落地）登记四个新横切机制：M19 截图与 OCR 接入（上一批已实现、未提交，本批同批核销）、M20 热键注册表、M21 点击穿透两态窗口、M22 岛活动仲裁。按变更纪律（`docs/MECHANISMS.md` 头部"登记即承诺"），新机制必须写入注册表；但登记后 `MECHANISMS.md` 达 1952 词，超出 1550 词上限（`scripts/manifests/doc-budgets.manifest.json`）。

## Decision

先精简、后放宽：

- **精简四行新登记**（M19/M20/M21/M22）：压缩为最小可承诺表述——选用机制唯一、禁止的重复机制、关联护栏三列保留 load-bearing 语义，去除过程性描述（如"按 Id 分派""会话清理+temp 策略"等展开细节），共删约 160 词。
- **上调 MECHANISMS.md 上限 1550→2000**（`scripts/manifests/doc-budgets.manifest.json`）：理由为新增真实机制条目，属变更纪律强制登记项（先例：2026-09-14 同因登记 M17/M18 上调 1400→1550）。上限调整后在限内并留约 2.5% 余量，余量小于上次先例（5%），故本次同时登记"下次全库巡检须复核该文档膨胀"义务。

## Alternatives considered

- **继续压缩至原上限 1550**：需再删 400+ 词。可删对象仅剩各行的「禁止的重复机制」与「关联护栏」列——这两列正是防重复实现与防已知问题的承诺面（如"第二套钩子/解析器""静默覆盖冲突""劫持引擎内置三键"），删掉即丧失登记价值。
- **拆分文档规避上限**：MECHANISMS 已是全仓横切机制的唯一真相源，拆分会产生"同域两个家"，违反"一个事实一个家"。
- **不登记新机制**：违反变更纪律"登记即承诺"，后续批次无机制基线可查。

## Consequences

- MECHANISMS.md 上限提至 2000，当前 1952 词在限内（doc-budgets 门禁转绿）。
- 登记内容即承诺：M20/M21/M22 的选用机制、禁止清单、护栏成为后续批次（热键侧板 P5、岛渲染 P3、点击穿透接线 P5）的强制约束。
- 本批同时将 M19（上一批已实现未提交）纳入登记，统一机制基线。
- 下次全库巡检须复核 MECHANISMS.md 词数，防止上限成为膨胀借口。
