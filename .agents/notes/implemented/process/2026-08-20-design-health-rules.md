# Agent Note: 设计健康规则落地——统一 UI 地基、功能复用反臃肿、扩展与社区契约

Status: implemented — 2026-08-20，P0 交接增强的延续

## Problem

现有治理体系管住了「怎么写」（门禁、决策记录、红线）与「怎么写代码」（coding-standards），但「写成什么样才健康」没有成文：全局字体、窗口属性、主题令牌等可复用资产没有唯一来源规则；功能复用与包粒度没有判据，臃肿无法预防；扩展点、插件清单、API 兼容策略没有对外契约，社区贡献者无从自助。用户明确要求把这些「对程序设计健康有益」的规则一并定下，目标形态对标 DeepSeek Harness 的高扩展、可社区结构。

## Decision

1. 新增 `docs/ui-foundation.md`：全局字体三令牌、统一 `ShellWindow` 窗口属性、语义化主题令牌、公共控件/转换器/资源单一来源，载体包规划为 `packages/shell/shell-foundation`（P2）。
2. 新增 `docs/reuse-rules.md`：单一实现、共享层上移、包粒度判据表、禁止复制粘贴、依赖方向单向、能力收敛六原则，并给出反臃肿红线（公共类型数/方法行数）。
3. 新增 `docs/extension-rules.md`：扩展点显式化、plugin.json v1 字段草案（P1 由 ADR-002 冻结）、语义化版本与弃用流程、文档与示例义务、社区贡献门槛。
4. 新增根目录 `CONTRIBUTING.md`：社区贡献者的最低门槛清单。
5. MECHANISMS.md 登记 M6（统一 UI 地基）/ M7（功能复用与反臃肿）/ M8（扩展性与社区契约），并把 M3 的枚举改为指向 run-gates 注册表（避免两处维护发散）。
6. coding-standards.md 增补两条禁止项（UI 硬编码、复制粘贴）并指向三份新规范；AGENTS.md 文档纪律同步挂靠；TERMINOLOGY.md 增补「扩展点/语义令牌/UI 地基/外壳窗口基类」术语。
7. **诚实标注机检状态**：三份新规范每条规则都标注「已有机检」或「暂无机检（靠评审）+ 规划机检」。当前多数 UI 规则暂无代码可查，P1/P2 落地 `verify-code-duplication`、`verify-ui-hardcoded`、架构测试等机检——规则先于代码，机检紧随代码。
8. 字数预算调整：`MECHANISMS.md` 上限由 700 放宽至 900（新增 M6–M8 登记行所致）；新增三份规范与 `CONTRIBUTING.md` 的预算条目。

## Alternatives considered

- 把三份规范塞进 coding-standards.md：否决——该文件管单文件代码风格，混入资产/复用/社区契约会互相稀释，且各自有独立受众（插件作者只看 extension-rules）。
- 等 P2 有 UI 代码后再定 ui-foundation：否决——「先有代码后有规则」正是老仓主题系统硬编码泛滥的成因；规则先于代码，才能让第一行 XAML 就按令牌写。
- 现在就实现全部机检：否决——无代码可检，空转门禁只会制造假绿；按 R1「门禁先于业务」的同一逻辑，机检跟随对应代码阶段落地，并如实标注。

## Consequences

- 后续任何 UI 代码、复用决策、对外契约都有唯一规范可依；社区贡献者冷启动路径闭环（CONTRIBUTING → 各规范 → 门禁）。
- P1/P2 的验收判据新增三组机检项（重复检测/依赖方向/UI 硬编码扫描），与「每阶段可运行」红线并列。
- 维护义务：三份规范与 MECHANISMS M6–M8 互为挂靠点，改动须互相确认指得通（同 ADR-001 F5 的双向对齐义务）。
