# Agent Note: 第二轮缺口补全——评审制度、并发纪律、格式单一来源、输入与主题安全面、ADR 分工

Status: implemented — 2026-08-20，用户提出「总觉得还少了点什么，不能落下」

## Problem

对规则框架做第二轮系统盘点，确认五处实质缺口：其一，代码评审制度完全缺失——门禁拦不住的（规则空白处自由发挥、夹带改动、伪证采信）全靠评审，但「评审查什么、合入怎么判、争议怎么裁决」无文可依；其二，并发与线程模型只有零散禁令（UI 线程外禁碰 UI），没有成套纪律（sync-over-async、裸线程、锁内等待是外壳类程序死锁与卡死的第一来源）；其三，代码格式没有单一来源（连 `.editorconfig` 都不存在，P1 一写代码必然漂移）；其四，安全面漏了两条真实攻击面——全局热键/输入钩子等于键盘监听权限、WPF 资源字典可实例化任意类型（社区主题包 = 代码执行面）；其五，ADR 与 Agent Note 的分工从未写明，决策者不知道该写哪一类。

## Decision

1. 新增 `docs/code-review.md` 并登记 M15：评审检查单（6 项）、合入门槛（独立评审 + main 保护 + 争议裁决路径）、评审责任（规则空白不放行、留痕、物证同责）。
2. `docs/coding-standards.md` 新增「五、并发与线程模型」：UI 线程唯一（Dispatcher 封送）、禁 sync-over-async、`Async` 后缀与取消令牌传播、禁 `async void`、禁裸 `new Thread`、锁内禁异步等待、`IDisposable` 确定性释放。
3. 新增根 `.editorconfig`（UTF-8 / LF / Allman 大括号 / 缩进分级），coding-standards 明确「格式唯一来源 = .editorconfig；P1 起 `dotnet format --verify-no-changes` 入门禁」。
4. `docs/security.md` 补两条：全局热键/输入钩子属敏感权限（集中注册 + 冲突检测 + 用户可见）；主题/资源包与插件同等待遇（签名与确认同级）。
5. `docs/extension-rules.md` 新增「六、打包与分发」：插件包 = 压缩包 + 清单 + 完整性哈希 + 可选签名；安装即校验；审核分级（签名免确认 / 未签名显式确认 / 行为越界下架熔断）。
6. `.agents/notes/README.md` 写明 ADR 与 Agent Note 分工：冻结项/机制替换/内核 API 方向 → ADR；其余非平凡决策 → Agent Note；拿不准先写 Note 再升格。
7. 明确**不在此处重复**的领域：配置系统、服务生命周期、事件契约属于内核设计，归 ADR-002 冻结，治理层只挂验收清单（pluginization.md 已立先例）。
8. 字数预算调整：`coding-standards.md` 由 850 放宽至 1100（并发纪律所致）；新增 `code-review.md` 预算条目。

## Alternatives considered

- 把并发纪律塞进 runtime-health：否决——并发是「怎么写代码」的约束，属 coding-standards 域；runtime-health 只管运行期健康现象。
- 现在就把 `dotnet format` 门禁上架：否决——仓库尚无业务代码，空转门禁制造假绿；P1 第一行代码落地时同步上架并取红证。
- 主题包安全只写一句提醒不升级为规则：否决——WPF 资源字典可实例化任意类型是公开代码执行面，社区主题生态一旦开放就是默认入口，必须与插件同级对待。

## Consequences

- 合入路径闭环：作者写码 → 门禁（机器）→ 评审（人）→ 合入（main 保护），三道闸各自成文。
- P1 验收新增：`.editorconfig` 生效 + `dotnet format` 门禁上架（含红证）。
- 社区主题/插件分发有了完整信任链条：打包 → 校验 → 分级确认 → 运行期熔断。
