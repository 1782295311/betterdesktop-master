# Agent Note: 插件化行为规范落地——角色插槽、替换原子性、崩溃隔离与熔断回退

Status: implemented — 2026-08-20，用户提出「社区不满意的部分要能快速替换且不引发崩溃」

## Problem

已有的 extension-rules.md 只约束插件契约（清单字段、扩展点声明、API 兼容），但**行为面**没有规范：社区插件如何替换内置功能、替换失败或插件崩溃时外壳如何自保、用户如何一键回退。没有行为规范，P1 内核可能做出一套「能加载但不能安全替换」的插件系统——这正是老仓扩展宿主模型的教训（热插拔有、隔离有，但替换语义与回退锚点从未定义）。

## Decision

1. 新增 `docs/pluginization.md` 并登记 M14，七节内容：
   - 角色插槽模型：功能面 = 角色 = 服务名；同名 provide 即替换；依赖者自动重载（ADR-001 §2.3 已冻结的 inject 机制，插件无需写通知代码）。
   - 替换原子性：先立后破（新提供者激活后才卸载旧 fiber），任一步失败整体回滚，禁止桌面中间态，全程超时。
   - 崩溃隔离分级：L0 进程内 PluginGuard（默认）/ L1 进程外 worker（声明制）；默认实现永远可用作为回退锚点。
   - 熔断与回退：连续 3 次崩溃熔断禁用、持久化禁用防循环崩溃、状态中心一键恢复内置。
   - 快速替换用户路径：用户级 Plugins 目录、免重启热切换、状态中心可见可操作。
   - 兼容护栏：`kernel-abi` 最低版本不匹配拒绝加载且明确报错；必需/可选依赖语义。
   - 验收判据：P2/P3 swap drill 与崩溃注入演练，物证按 guard-redproof 标准。
2. `docs/architecture.md` 内核要点表补「替换」一行；`docs/extension-rules.md` 增加与行为规范的分工说明。
3. 术语表增补：角色 / 回退锚点 / 熔断 / 替换（TERMINOLOGY 预算随之由 900 放宽至 1100，理由即本记录）。

## Alternatives considered

- 并入 extension-rules.md：否决——契约与行为受众不同（插件作者读契约，内核实现与评审读行为），且行为规范随 P1/P2 会显著增长。
- 替换语义用「显式注册表」而非「服务名即插槽」：否决——那要求内核维护第二套登记机制，违反 M5「一切皆插件」的单一通道原则；Cordis 的 provide 同名覆盖语义天然就是插槽。
- 把熔断阈值定为 1 次：否决——一次异常可能是瞬时故障，3 次熔断在「快速止损」与「不误伤」之间平衡；阈值本身后续可按演练数据调整（调整需决策记录）。

## Consequences

- P1 内核 API 冻结（ADR-002）必须显式支持本文件的一至六节语义，否则 ADR-002 不可批准——行为规范成为内核设计的验收清单。
- P2/P3 验收新增三组演练物证（替换 / 崩溃注入 / 状态中心），与「每阶段可运行」红线并列。
- 社区替换安全性的承诺由此成为可验证项，而不是口号。
