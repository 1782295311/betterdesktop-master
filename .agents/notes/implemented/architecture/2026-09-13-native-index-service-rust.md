# Agent Note: 原生索引服务——Rust 常驻进程承载应用/文件/图标事实

Status: implemented

## Problem

三类消费者各自重复付出扫描代价，且都没有可用的常驻索引：

- 文件搜索依赖系统 Windows Search（服务禁用或目录未索引即返空），兜底是递归目录枚举并带 1.5s 超时，输入过程中触发会明显卡顿。
- 应用源全量扫描：开始菜单全递归、注册表三视图、全程序盘点深度 3；实测冷启动量级分别为数千毫秒与数十秒，只能靠 2 分钟内存缓存缓解。
- 图标提取在四处各自实现（应用源、菜单栏、右键菜单、剪贴板），逐文件调用 Shell API，缓存互不复用。

这些事实（磁盘上有哪些 exe、哪些文件、某个文件的图标）本可以由一个常驻进程持有并增量维护，而 C# 侧维持 GB 级索引会带来 GC 压力与大堆。

## Decision

新增 Rust 常驻服务 `engine-index`（`BetterDesktop.Index.Engine`），一次遍历产出应用/文件候选与图标字节；C# 侧新增客户端包 `shell-index-ipc`（`IndexEngineClient` + `IndexEngineLauncher`），消费者按后端开关接入。

关键约定：

- **权威源划分**：引擎只输出 raw candidate（路径 + 名称候选 + 来源根标记），**不输出 `AppItem` 语义**（固定态、分组、Id、图标键）；Id、显示名、过滤与分组仍由 `shell-app-source` 产出，避免双份事实。
- **排序不搬**：搜索排名与分类留 C# 侧（`ScoreFileName` / Provider Score），引擎只返回候选与原始匹配信息。
- **图标切面窄**：引擎只产一档 256×256 PNG 字节并缓存 PNG 字节（LRU + 字节上限），缩放归 C#（`DecodePixelWidth`），故 `IAppIconService.GetIconAsync(size)` 契约与全部调用方零改动。
- **协议**：管道 `BetterDesktop.Index.Engine`，首帧 magic `BDIX1|`，JSON-RPC 行协议；图标走同一管道上的长度前缀二进制帧（上限 2MB），不依赖跨语言计划的共享内存阶段。
- **降级必须可见**：引擎未部署 / 未连接 / 仍在构建 / IPC 异常时一律回退本地实现并记 Warn，设置中心「索引服务」状态行显示运行状态、条目数、RSS、上次重建耗时与降级原因；`backend` 可强制为 local 供排障。
- **权限边界**：主路径（枚举 + Shell 图标）不得要求管理员；USN Journal 只作为可选快路径并需能力探测。
- **内存自管**：引擎是独立进程、不在 `IResourceGovernor` 的插件 subject 域内，因此由引擎自管（配置上限 + LRU 驱逐 + `status` 上报 RSS），不为一次性需求改内核契约。

## Alternatives considered

- **接入 Everything SDK**：省去索引实现，但引入第三方依赖与分发/许可约束，且应用枚举与图标不在其职责内，无法覆盖三个消费者。
- **仅在 C# 内加缓存或异步化**：解决不了冷启动全盘扫描的量级，也解决不了 GB 级索引在托管堆上的内存放大。
- **以 USN Journal / MFT 作为主路径**：需要卷句柄与管理权限，破坏"安装即用"，仅保留为可选快路径。
- **让引擎直接产出 `AppItem`**：会导致固定态/分组/Id 出现第二份权威，切换后端时条目集漂移。
- **把索引并入宿主或 Agent 进程**：索引构建是长任务且内存占用大，与壳的交互延迟目标冲突，独立进程同时获得崩溃隔离。

## Consequences

- 引擎首次构建是异步的，构建期间 `list_apps` 报"不可用"、消费者回退本地，因此首次启动不会因为索引未就绪而功能缺失，但会短暂走慢路径。
- `engine-index` 与 `app-source` 的分工成为硬边界：任何"引擎顺带算一下应用语义"的改动都会破坏单权威源。
- 回退路径必须随主路径同步维护（两条实现长期并存会腐烂），因此回归测试需覆盖 `backend=local` 的逐行为不变，并保留强制回退开关。
- 图标"只取一档大图"与既有"普通应用取 ExtraLarge(48) 原生帧、防字形过度缩放"的红线相反；解法是解码后按 alpha 包围盒归一化再缩放。真机并排对比若仍有明显字形占比差异，则退回按 size 取原生帧，一档大图的收益只保留给对占比不敏感的场景。
- 部署面增加一个原生 exe 与一次 cargo 构建（`scripts/deploy-index.ps1`），并新增 `shell-index-ipc` 与其测试工程。
