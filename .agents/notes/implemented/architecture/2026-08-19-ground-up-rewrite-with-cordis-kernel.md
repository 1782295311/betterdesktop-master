# Agent Note: 另起炉灶——以 Cordis 内核与双重纠错机制从零重写桌面外壳

Status: implemented — 2026-08-19 用户拍板，P0 同日落地

## Problem

旧仓 `cairoshell原版` 经过多阶段治理后已经能编译、有成熟的扩展宿主与护栏文化，但三处结构性限制无法在旧结构上解决：其一，扩展模型是「外挂式扩展宿主」（内核功能本身不是插件），拿不到 Cordis「一切皆插件 + 服务图 + 依赖驱动重载」的结构性收益；其二，net480 双 TFM 使 AssemblyLoadContext 在旧目标下不可回收，HMR 与插件卸载永远打折扣；其三，文档治理全靠人肉（包级 README 覆盖率 1/32，断链、预算、决策记录格式没有任何机器校验）。

## Decision

推翻「旧仓内改造」路线，另起炉灶全量重写，并明确与 cairoshell 结构切割：

1. 新仓 `better-desktop-cordis`（D1）。
2. 技术基线仅 net8.0-windows + WPF，放弃 net480（D2）。
3. 第一步只做 P0 地基：宪法 + 门禁 + 决策记录制度 + 变红物证，不写任何业务代码（D3）。
4. 旧仓只读作行为参考：逻辑代码零复制；主题、图标、XAML 一律不复制；唯一可借鉴的是白名单内的原生结构体布局，逐条 ABI 核对后登记（D4）。
5. 宪法七条红线与双重纠错机制落地清单，冻结于 ADR-001；机制唯一化登记于 MECHANISMS.md（M1–M5）。

## Alternatives considered

- 旧仓内绞杀者迁移：否决。受旧 ADR 冻结项牵制，且扩展宿主形态与内核形态结构性冲突，迁移到一半必然两头妥协。
- 沿用 cairoshell 命名：否决。用户明确要求与新结构切割，命名本身是结构信号。
- P0 + P1 连做：否决。违反红线 R1——门禁未经红绿验证就开始写内核，等于裸奔。
- 照搬 DSH 的 Node/TS 脚本体系：否决。C# 项目无需引入 Node 运行时；机制全部用 PowerShell 原生复刻，零新依赖。
- 复制旧仓主题与图标：否决（D4）。视觉资产全部重建，这是「另起炉灶」的题中之义。

## Consequences

- P0 阶段无任何用户可见功能；接受这一代价换来的是「每一条门禁都会变红」的可信地基。
- 主题、图标、UI 全部重建，短期工作量大于改造路线。
- 内核级热重载、插件隔离、每包可验证成为一等能力；文档与代码由机器对齐。
- 旧仓从此只读：行为对照时以旧仓 commit `a5e6b49`（2026-08-19 实测 HEAD）为基准，对照清单固定到该 hash。
