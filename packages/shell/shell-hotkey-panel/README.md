# BetterDesktop.Shell.HotkeyPanel

热键对用户可见的部分（热键计划 P5）：宿主内**常驻热键侧板**（显示与隐藏管理）+ 设置中心「热键」分节（**改键的唯一入口**）。

## 组成

| 文件 | 职责 |
|---|---|
| `HotkeyPanelPlugin.cs` | 宿主插件：`context.Get<IHotkeyRegistryService>()`，创建常驻侧板窗口 + 一次性声明迁移既有热键 + 注册设置分节 |
| `HotkeyPanelWindow.cs` | 常驻透明窗：只读实时热键表（冲突/被接管置顶高亮）+ 右 Alt 门控可操作态（隐藏 / 已忽略管理 / 打开热键设置 / **右键菜单** / 关闭侧板）+ 拖动记忆位置 |
| `HotkeyPanelSettings.cs` | 侧板显隐设置键（`hotkeys-panel.enabled`）与切换热键标识（`hotkeys-panel.toggle` / `Ctrl+Alt+H`）的**单一真相源**——三条入口只写这一个键 |
| `HotkeyPanelState.cs` | 侧板交互状态机（纯模型：ReadOnly / Interactive / Manage）——可单测 |
| `HotkeyListModel.cs` | 列表纯逻辑（冲突置顶排序 / 隐藏过滤 / 忽略计数 / 非活跃作用域徽标）——可单测 |
| `HotkeyDeclarations.cs` | 声明迁移清单（paste-back / capture / 引擎三键 / 开始菜单 + **93 条系统热键与通用键 / 6 组**）+ capture 配置**读-改-写**（`PatchCaptureJson`） |
| `HotkeyScanner.cs` | 全局热键占用扫描器（`RegisterHotKey` 试注册探测，归类系统 / 自家 / 第三方） |
| `ThirdPartyHotkeyCatalog.cs` | 常见第三方软件默认全局键 + 进程探活（钩子式热键的归属线索） |
| `AppHotkeyCatalog.cs` | **应用场景热键目录**（Blender / VS Code…）：进程名 → 分组功能键，支持裸键；按前台应用置顶显示 |
| `ForegroundAppWatcher.cs` | 前台应用探测（500ms 轮询前台窗口取进程名；**不引入任何钩子**，probe 可注入以便单测） |
| `HotkeyCaptureKeys.cs` | 录键校验（复制自设置中心 HotkeyRow 模式，勿跨包重构） |
| `Sections/HotkeySettingsSection.cs` | 设置中心「热键」分节：可自定义 / 全局（截图·引擎）/ 第三方 / 系统（折叠）/ 检测 |

## 交互

- **侧板只读态**：常驻屏幕右侧（可拖动，位置记忆 `hotkeys-panel.x/y`，始终钳制在工作区内），高度按屏高自适应（30%–70%，夹 300–640），完全点击穿透；列表 = **自家热键 + 系统热键常用子集（16 条）**——穿透态滚轮会落到下方应用、**滚不出来**，所以只读态只放常用的。
- **侧板可操作态**：按住右 Alt + 点击侧板进入；行内「隐藏」+ 底部「已忽略 N 项 · 管理」+「打开热键设置」。**松开右 Alt 不退出**——退出靠「点击面板外 / 空闲 15 秒 / 完成」。这里是**全量列表**（自家 + 冲突 + 63 条系统热键），列表包在 `ScrollViewer` 里，**用滚轮翻看更多**（只读态做不到，因为穿透）。
- **门控用 50ms 轮询，不用任何全局钩子**：`GetAsyncKeyState`（右 Alt / 左键 / Ctrl）+ `GetCursorPos` + 窗口矩形判定。低级钩子必须由 UI 线程处理回调，UI 一忙就会被系统挂起输入甚至静默摘钩（真机症状：菜单栏点不动）——轮询是纯"拉"模式，零阻塞、零失效。
- **侧板永不激活**：可操作态保留 `WS_EX_NOACTIVATE` → 不抢前台、不切换输入法、不影响菜单栏状态。
- **拖动为手动实现**：`CaptureMouse` + 屏幕物理 delta ÷ DPI 换算，**禁用 `DragMove()`**（见纪律）。
- **设置中心改键**：点键位胶囊直接录键（Accent 高亮 + 状态行），Backspace 停用，Esc 取消；改完按**三态**如实回报——已重启立即生效 / 已保存（进程未运行，下次启动生效）/ 重启失败。
- **设置中心隐藏**：每行（含系统热键行）都有「隐藏 ↔ 显示」——隐藏 = **不在热键侧板里显示**，键位注册状态与功能一律不动（红线「隐藏 ≠ 静音」的用户入口）；设置中心始终显示该行，可随时恢复。条目未声明时按钮置灰（不做假操作）。
- **通用编辑 / 浏览键**：`Ctrl+C/V/X/Z/A/S/F` 这类是**应用层约定**（由各程序或系统编辑控件实现，不经 `RegisterHotKey`），清单里独立成两组并标注「应用内生效，非全局」，不与系统全局热键混为一谈。
- **场景置顶**：切到已收录的应用（Blender / VS Code 等）时，侧板**最上方**先列该应用的功能键（`▶ Blender（当前应用 · 33 个功能键）`），再接通用热键表；未收录的应用不占位置。目录可在 `AppHotkeyCatalog.All` 加一条 `AppHotkeyProfile` 扩展，完整清单见设置中心「热键 › 应用热键」。
- **第三方热键**：进分节自动扫描一次（互斥 + 缓存）。**扫描前必须做 F24 校准**——`Win+*` / `Ctrl+Win+*` / `Ctrl+Shift+Win+*` 是 Windows **保留组合**（连 F24 都注册不上，错误码与"被占用"同为 1409），未校准时会被大量误报成第三方。每条按知识库反查给出**疑似来源与功能**（命中且该软件在运行时标"可能性高"），并显示**改键位置**（如「微信 → 设置 → 快捷键」）；命中且在运行时可「打开该软件」直达；查不出就如实显示"归属未知"，并可用**对比上次扫描**（新增/已释放明细）定位归属；每条可「忽略」（持久化 `hotkeys-panel.thirdparty-ignored`，只影响显示），底部可恢复。**不改动别人的键位**。
- **检测快捷键**：按下组合键 → 系统热键 / BetterDesktop（区分已停用·进程未运行·仅某界面生效）/ 被占用三分支。
- **侧板显隐（启动 / 关闭 · 2026-09-17）**：侧板原来只随宿主常驻、用户没有任何关闭入口。现在显隐由设置键 `hotkeys-panel.enabled` **唯一表达**，三条写入口同源、落地统一在插件订阅的 `ShellEvents.SettingsChanged` 里执行（不会出现"菜单关了、设置里还显示开"的漂移）：
  ① **右键菜单**（可操作态可达）：勾选项「显示热键侧板」= 开关本体（取消勾选即关闭），右侧显示当前切换热键；再一项「打开热键设置」；
  ② 可操作态底部「关闭侧板」文字入口 —— 右键菜单万一不可达（WPF 弹层在 NOACTIVATE 常驻窗上的边界情况）时的**保险丝**，不依赖菜单也不依赖热键；
  ③ 设置中心「热键 › 热键侧板」勾选框（**关掉之后仅剩的两条回家路之一**）。
  **再打开**：全局热键 `Ctrl+Alt+H`（`hotkeys-panel.toggle`，注册进注册表 → 出现在侧板列表与本页「全局热键」区，可改键/可停用/冲突时如实提示）或上面的勾选框。
  > 右键菜单**只在可操作态可达**：只读态整块点击穿透（点击/右键都落到下方应用），与行内「隐藏」同一前提。
  > 隐藏会同时停掉 50ms 门控轮询与 500ms 数据轮询（不在屏幕上就不该占着定时器）；重开时回到只读穿透态。

## 依赖

- `hotkeys` 插件（`IHotkeyRegistryService`，缺失时降级不创建窗口，M10）。
- `ISettingsService`（配置键读写 + 侧板位置记忆）、`ISettingsWindowService`（跳转热键设置）。
- shell-core（PopupWindowBase / ClickThroughWindow / RightAltGate / HotkeyScopeTracker）、shell-clipboard-ipc（HotkeySpec / ClipboardEngineLauncher）。

## 关键纪律

- **不双注册**：既有热键以 `Declare`（声明不注册）进注册表，宿主不重复注册（0x581 红线）。
- **声明 ≠ 注册**：展示与检测必须区分"已声明"与"真注册且进程在跑"（进程探活 + Enabled + 作用域），不给用户"按了有反应"的假承诺。
- **改配置不覆写**：capture 的 settings.json 一律读-改-写（`PatchCaptureJson`），禁止整份 `WriteAllText`（会丢 `stickerTopmost` 等字段）。
- **改键不无故拉起进程**：只在目标进程**正在运行**时重启；未运行则只保存配置，下次启动生效。
- **扫描边界**：只能发现 `RegisterHotKey` 注册的全局热键；钩子式热键（输入法、多数截图/聊天工具）探测不到，占用者也**不可知**——UI 必须写明，不得暗示"没列出来 = 没被占用"。
- **扫描串行**：两个扫描并发会互把对方的试注册当成"被占用"→ 必须互斥（`ScanGate`）。
- **数据刷新**：500ms 轮询注册表纯读接口（跨包类事件订阅需 IEventBus 桥接；轮询零跨包事件）。
- **隐藏 ≠ 静音**：隐藏仅过滤显示，不改键位注册状态。
- **侧板显隐单一真相源**：侧板在不在屏幕上只由 `hotkeys-panel.enabled` 表达。任意入口（右键菜单 / 底部入口 / 设置勾选 / 切换热键）都必须**先写这个键**，窗口的 Show/Hide 只是幂等的落地动作——禁止"只 Hide 不写设置"（设置中心会与实际相反）或"只写设置不落地"（点了没反应）。注册开关热键是 `Register` 而非 `Declare`：卸载必须 `Unregister` 释放键位，否则重启后新宿主注册不上（0x581）。
- **关闭侧板的兜底路径必须有**：右键菜单是用户要的入口，但它依赖 WPF 弹层在 `WS_EX_NOACTIVATE` 常驻窗上的可用性；侧板是本机常驻浮层，必须另有一条"不依赖菜单、不依赖热键"的关闭路径（可操作态底部「关闭侧板」）+ 一条"关掉后能回来"的路径（设置中心勾选）。
- **常驻浮层禁用低级钩子做门控**：`WH_MOUSE_LL`/`WH_KEYBOARD_LL` 的回调由安装线程（UI 线程）处理，UI 一忙就会超过 `LowLevelHooksTimeout`（默认 300ms）→ Windows 挂起**全局鼠标输入**并可能静默摘钩（真机症状：鼠标点不动任何东西、菜单栏无法触及）。改用轮询：`GetAsyncKeyState` + `GetCursorPos`，纯拉模式零阻塞。
- **禁用 `DragMove()`**：对 `WS_EX_NOACTIVATE` 分层窗口调用会进入系统移动循环 + `SetCapture`，中途切样式导致循环异常退出时**鼠标捕获残留在侧板**上，之后全局点击都被定向到它 → 手动拖动。
- **不穿透浮层必须有非钩子退出路径**：点面板外 / 空闲超时 / 显式关闭按钮，且位置必须钳制在工作区内（不得盖住菜单栏/任务栏）。
- **不编造归属**：第三方热键反查不中时必须显示"归属未知"并给排查办法；「忽略」只影响显示，绝不改动他人配置。
- **扫描先校准，否则假阳性**：`Win+*` / `Ctrl+Win+*` / `Ctrl+Shift+Win+*` 是 Windows 保留组合（错误码同为 1409），必须先用 F24 探针判定修饰键组合是否被保留，保留的一律归"系统保留"——否则第三方清单会被灌入几十条系统噪音。
- **不代改他人配置**：微信/QQ 加密存储、NVIDIA 走专有面板，代改代价大于收益；只提供"来源 + 功能 + 改键位置 + 打开该软件"，把路铺到门口。少数明文配置软件（Snipaste `config.ini`、PowerToys json）才有直改可能。
- **界面颜色一律走令牌**：禁止硬编码色（`Brushes.White` / `Color.FromArgb`）——这是高对比度主题与主题切换的前提（也是 UI Pro Max 对 WPF 的硬规则）；取色入口 `ThemeBrushes`，令牌全集见 `host/App.xaml`。按钮统一**胶囊**且带 hover/pressed 反馈（`HotkeyPanelVisuals` 隐式样式）。
- **窄面板的排版纪律**：键位列用**固定宽度**（`Width`，不用 `MinWidth`）保证描述列对齐；截断的长文本必须补 `ToolTip`（保整齐但不丢信息）。
